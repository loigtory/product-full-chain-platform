# CAP-PFC-01 T5 GateRun 与路由实施检查点

> 记录时间：2026-09-05 05:57:00 +08:00  
> 分类：System Iteration / strict  
> 授权：用户授权 T4 后连续执行后续 Txx；本阶段仅执行本地 T5  
> 设计基线：`REQ-PFC-001 V0.7`、`CAP-PFC-01 V0.1/R4`、`G9-A DESIGN_CONFIRMED`

## 1. 目标与非目标

- 实现 `UNIT-PFC-01-04` 和 `AC-CAP-PFC01-04-01～10`：自动/人工 GateRun、阻断、并发复用、PASS 单次推进、WARN、check-level N/A、UNKNOWN 恢复及旧基线迟到结果。
- GateRun 绑定 Requirement、当前 stage 和 baseline；只有 `CURRENT + PASS` 在同一数据库事务内写唯一 StageAdvancement 并推进相邻阶段一次。
- 自动运行调用现有 `GateExecutionPort` fixture/unavailable 边界；真实 PFC-03 不可用时不创建自动运行，保留人工登记入口。
- 本阶段不实现 T6 baseline 影响切换、时间线分页/SSE，不实现真实 PFC-02/03/04/05，不执行默认 schema migration，不 commit/push/merge/发布/部署。

## 2. 已选实现语义

1. 自动运行前先以只读 capability probe 判断执行端口。UNAVAILABLE/UNKNOWN 时拒绝创建 GateRun；AVAILABLE 后才在数据库中抢占当前 Requirement+baseline+stage 唯一 IN_PROGRESS。
2. 不同幂等键并发时，Requirement 行锁和唯一索引保证只有一个新运行；后续请求保存自己的幂等映射并返回同一 IN_PROGRESS，只有创建者调用执行端口。
3. OPEN/ANSWERED 且已到 `closeByStage` 的 Question 直接生成本地 BLOCK checks，不调用外部执行端口。DEFERRED、CONFIRMED 和 SUPERSEDED 不构成该项阻断。
4. 执行端口返回 ACCEPTED/RUNNING 时保留 IN_PROGRESS；返回 COMPLETED 时写结果；返回 UNKNOWN、调用异常或运行后能力丢失时将已创建运行完成为 UNKNOWN，并提供只读恢复入口，不自动重跑。
5. 人工 GateRun 只接受总体 PASS/BLOCK/WARN；N/A 仅可用于 GateCheck。PASS 必须至少有一个 PASS check 且没有 BLOCK/WARN；BLOCK/WARN 必须有对应 check，避免伪造总体结论。
6. 人工运行必须有非空登记说明、适用责任角色确认、至少一个当前 baseline 的 VALID EvidenceRef 和至少一个 GateCheck。证据先做 Requirement 动作授权，再通过 ArtifactEvidencePort 校验；受限证据再按其敏感等级重验访问权限。
7. 完成事务锁定 GateRun 和 Requirement，按当前 stage/baseline 决定 `CURRENT`、`INVALIDATED` 或 `STALE_BASELINE`。旧基线 PASS 只保留历史，不改当前阶段。
8. 同一 PASS 重放读回同一 advancement；数据库 `gate_run_id` 唯一和阶段推进触发器是最终防线。G12 PASS 记录但不越界推进。

## 3. 接口与投影

- `POST /api/v1/requirements/{id}/gate-runs/automatic`：body 绑定 `stage/baselineId`，要求 `Idempotency-Key` 与 Requirement `If-Match`。
- `POST /api/v1/requirements/{id}/gate-runs/manual`：在上述绑定外携带总体结论、登记说明、确认角色、EvidenceRef IDs 和 GateChecks。
- `GET /api/v1/requirements/{id}/gate-runs/{runId}`：按当前 Requirement 权限读取权威运行结果，供 PROCESSING/UNKNOWN 刷新恢复。
- `GET /api/v1/requirements/{id}` 增加当前 GateRun、历史摘要和执行能力；工作清单的 gateProjection/nextAction 由服务端持久化状态派生。
- 错误沿用 `DEPENDENCY_UNAVAILABLE`、`RUN_ALREADY_IN_PROGRESS`、`RESULT_UNKNOWN`、`STALE_BASELINE_RESULT`、`VERSION_CONFLICT`、`PERMISSION_DENIED` 与稳定恢复动作；错误/outbox 不包含材料正文、人工说明或检查原因。

| 断言     | 同一 tuple 最多一个 IN_PROGRESS；PASS 只推进一次；非 PASS/旧 baseline/非当前 stage 不推进；N/A 不成为总体结果；历史不覆盖                        |

确定性 factory 由并发、权限、版本、状态、负向和恢复场景共同触发，必须在报告 PASS 前实现。

## 5. 验证、风险与退出

- TDD 顺序：contracts/domain -> application/in-memory -> PostgreSQL transaction -> Fastify -> React -> PC Playwright。
- Quick/Core 必须 PASS；PostgreSQL 覆盖不同 key 并发、同一 PASS 多次完成、旧 baseline、约束和清理；浏览器覆盖三个 PC 视口的不可用/人工/自动结果状态。
- 重点风险：依赖不可用仍建运行、双外部执行、PASS 重复推进、迟到结果污染当前状态、无证据人工 PASS、N/A 提升为总体 PASS、受限证据越权、UNKNOWN 自动重试。
- 回滚仅反向编辑未提交 T5 源文件；不删除默认 schema 或非测试数据。
- 停止条件：必须改变已确认 GateRun 产品规则、需要真实外部执行/环境写入、无法保证单事务推进或发现越权材料读取。
- 技术退出不等于正式验收。代码评审、测试和安全责任人均为陈立；T5 正式接受仍取决于各项结论本身，不因人员登记阻断。
