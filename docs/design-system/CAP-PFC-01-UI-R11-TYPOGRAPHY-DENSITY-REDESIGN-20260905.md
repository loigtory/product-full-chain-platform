# CAP-PFC-01 UI-R11 排版与密度重建设计

> 分类：System Iteration Requirement / strict  
> 状态：工程实现与全量门禁已通过，待产品负责人视觉验收  
> 确认方式：产品负责人在获知“以真实参考站为唯一视觉基准，重建字体角色、信息密度、导航层级和表格模板；保留独立预览与数据库只读边界”后回复“继续”  
> 版本：UI-R11

## 1. 目标、非目标与事实基线

目标：修正 UI-R10 只复用了颜色与大标题、没有复现参考系统排版权重和高密度节奏的问题。UI-R11 以同一浏览器、同一视口读取的参考计算样式为准，重建中文字体栈、页面层级、导航语义、指标卡、筛选工具栏和数据表，并把可复用规则固化到三层 token、共享组件和 `/ui-kit`。

非目标：不替换 `/` 正式工作台；不改变需求、门禁或材料的业务行为；不新增菜单目的地、业务状态、指标口径、API、数据库字段或写入口；不安装字体、不引用外部图片或 CDN；不执行数据库写入、迁移、部署、发布、提交或推送。

事实基线：参考 `/analytics` 在 1440x900 Edge 中的关键计算样式为：顶栏 65px；H1 与指标数字 30/36、700；页面说明 16/24、400；指标标签、筛选和表格数据 14/20、400；表头 14/20、500、40px 高；筛选与搜索 32px 高；数据行 45px 高。UI-R10 的主要偏差是中文字体栈顺序错误、筛选 13px/600、表头 12px/600/48px、数据行 13px/64px，并存在装饰性指标顶线和抢占层级的数据源卡片。

## 2. 方案选择

候选方案：

1. 仅覆盖字号和行高：改动小，但品牌、标题区、筛选组合和表格层级仍然错误，不能解决产品负责人指出的整体差距。
2. 在独立预览中从排版和密度基础重建，并同步共享 token、组件模板与 `/ui-kit`：既能用真实数据验证，也保留正式页面隔离和整体回滚能力。
3. 先生成新的 Figma 或 AI 图片概念：适用于没有视觉来源的新设计；本次已有产品负责人指定的真实系统，再生成概念会形成竞争标准且无法验证真实交互。

已选方案：方案 2。参考站截图和计算样式就是本轮已接受概念，跳过 ImageGen。实现不得凭主观重新解释数值，确需产品化差异时必须说明业务原因。

## 3. 信息架构与可见文案

全局一级导航只保留已有真实模块，不创建空入口：

- `需求管理`：当前模块，进入需求工作台。
- `门禁中心`：沿用现有 `/gate-center`。
- `材料库`：沿用现有 `/material-library`。

需求模块内的视图范围使用 `全部需求 / 待我处理 / 阻断项`，属于同一工作台筛选，不冒充新的页面菜单。只读预览状态与账户放在顶栏右侧，数据来源和更新时间进入页面标题区的轻量元信息，不再使用独立卡片。

页面阅读顺序固定为：

1. 页面图标、`需求工作台` 和一句业务说明。
2. 由真实列表计算的四项概览：当前需求、阻断项、需关注、覆盖阶段。
3. 仅由当前列表推导的两块分布摘要：阶段推进与门禁态势；不请求或制造新数据。
4. 需求范围、搜索、排序、视图和刷新组成的一体化筛选条。
5. `需求列表 / 阶段分布` 工作面板与只读详情栏。

本轮不增加参考站特有的 Skill 来源、热度、安装量等结构；PFC 没有对应业务数据。同尺寸首屏复核确认现有列表可以确定性导出最早阶段、最前阶段、覆盖阶段、阻断、需关注和未开始数量，因此增加第二层分布摘要；列表为空时显示 `-` 和 `0`，不制造业务值。

## 4. 三层 token 与组件规格

Primitive：

- 字体栈：`Noto Sans SC, PingFang SC, Microsoft YaHei, -apple-system, BlinkMacSystemFont, Segoe UI, sans-serif`。
- 字号：12、14、16、18、20、30px；字重：400、500、600、700；字距固定 0。
- 主文字 `#333333`、次文字 `#666666`、品牌青 `#00A0E9`、强品牌青 `#0078C8`、边框 `#E8EDF2`、弱表面 `#F5F7FA`、白色表面。
- 间距使用 4px 基线；运营卡片圆角不超过 8px。

Semantic：

- 页面标题 `30/36、700`；页面说明 `16/24、400`；区块标题 `18/26、600`。
- 正文、表格数据与筛选 `14/20、400`；表头与导航 `14/20、500`；辅助信息 `12/18、400`。
- 页面画布为白色；弱灰只用于表头、hover 和次级分区，不使用大面积蓝灰底。

Component：

- `GlobalHeader`：65px，白色半透明表面，1px 底边框；品牌名使用品牌青；当前一级导航以文字颜色和 2px 底线识别。
- `MetricCard`：紧凑白色卡片，图标置于淡色底；标签 14/20、400，数字 30/36、700；删除装饰性顶部色条和抬升位移动效。
- `SummaryPanel`：两列白色摘要面板，标题与轻量元信息在上，三个真实统计项在下；不使用伪选中态，不嵌套卡片。
- `SegmentedControl / SearchField / SelectField / icon button`：统一 32px 高；14/20、400；选中项不额外加粗；键盘焦点保留品牌 ring。
- `WorkPanel`：区块标题 18/26、600，说明 12/18；不嵌套卡片。
- `DataTable`：表头 40px、14/20、500；数据行 45px、14/20、400；单元格水平 8px；名称链接 14/20、500；状态、时间和数字保持稳定对齐。
- `DetailSheet`：沿用只读、Escape 关闭和焦点恢复行为，正文采用相同排版角色。

## 5. 交互、数据与安全边界

- URL 继续保存 `scope`、`search`、`view`、`sort`、`selected`。
- 搜索、范围、排序、视图、刷新、详情打开和关闭行为保持不变。
- 页面只调用现有需求列表与详情 GET；不向组件传递 mutation 动作，不渲染新建、推进或保存入口。
- 浏览器验证记录所有 `/api/v1/**` 请求方法，出现 POST、PUT、PATCH、DELETE 立即停止。
- 本地 PostgreSQL 仅由现有 API 读取；不造数，无 createdIds 和清理项；测试数据仍使用 `CODEx_TEST_` 合成响应。
- 不引入外部字体或新依赖，因此没有新的网络、许可证、install script 或锁文件风险。

## 6. 影响范围、版本与回滚

预计修改：

- `packages/ui/src/tokens`：补齐参考主题排版与密度 component token。
- `packages/ui/src/components/components.css`：共享导航、指标、摘要、筛选和工作面板的参考主题状态。
- `apps/web/src/WorkbenchPreviewPage.tsx`、`workbench-preview.css`：调整信息结构和页面样式。
- `apps/web/src/UiKitPage.tsx`：让元素目录展示 UI-R11 主题与排版规格。
- 单元、UI 治理和 PC E2E：新增排版/尺寸/只读回归断言。
- 设计与质量报告：记录真实浏览器对照和剩余风险。

回滚：移除 UI-R11 的主题覆盖和预览结构调整，恢复 UI-R10 预览；正式页面、API 和数据库均无回滚动作。

## 7. 测试、验收与退出标准

TDD 顺序：先新增排版密度契约并确认因 UI-R10 当前值失败；再完成最小实现。比例化验证包括：

- 聚焦单元测试：只读边界、导航文案、信息层级、可复用元素目录。
- UI 治理：业务 CSS 不出现 raw color、font、radius、shadow 或 motion。
- PC E2E：搜索、筛选、视图、详情、Escape、回焦、GET-only、无控制台错误。
- 视觉契约：浏览器 computed style 精确验证字体栈、H1、指标标签/数字、32px 筛选、40px 表头、45px 数据行。
- 同一 Edge 浏览器分别以 1280、1440、1920 截取参考和本地实现；使用像素截图人工复核层级、密度、越界和状态。
- 运行 Quick 和 Core；UI 共享模板与关键浏览器路径变更后运行 Full Gate。

工程通过不等于视觉通过。UI-R11 只有在上述证据完整且产品负责人明确确认视觉后，才可进入正式页面迁移方案；代码评审、测试、安全责任人仍为 `陈立`，因此正式验收与发布继续阻断。

## 8. 协作、进程与发布边界

本轮不使用并行代理，因为 token、共享组件、页面和视觉契约紧密耦合。验证后关闭临时浏览器和测试进程；按用户要求保留本地 Web、API 与 PostgreSQL 体验服务，并在交付中报告 PID、端口、用途和停止命令。

本轮不发布、不部署、不提交、不推送。后续发布设计仍需单独给出制品来源、发布人、回滚、smoke、观察窗口、关键监控和明确授权。
