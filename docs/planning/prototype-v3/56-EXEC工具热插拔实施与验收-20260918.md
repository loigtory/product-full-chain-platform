# 56 号：EXEC 工具热插拔（host 工具注册表 + 配置装载）

> 日期：2026-09-18 · 分支：feat/ai-tools-integration · 状态：已完成
> 前置：55 号（阶段能力配置中心）+ 54 号（冻结计划执行链）均已交付

## 一、目标

55 号把 skill/tool/mcp 做成每阶段热插拔配置，但 **EXEC（真实执行）作业的 host 工具仍是硬编码**（config.js `hostThreadParams` 里写死 5 个 `pfc_*` 工具），不受配置表影响。56 号把这最后一段接通：

- dev 阶段在「阶段能力」页面配置的工具（如开发终端类工具），EXEC 作业启动时**按配置装载**；
- 装载必须经过**白名单注册表**（安全基线：不能允许任意配置名注入执行器）；
- 核心 5 个 `pfc_*` 工具**恒在**，不受配置影响（exec-control 批准执行语义不变）。

## 二、设计

```
页面（dev 阶段启用 tool）──► stage_capabilities 表
        └─► worker EXECUTE: enabledHostToolsForStage(db, tenant, stage)
              └─► host-tools-registry.resolveHostTools(names)   ← 白名单
                    ├─ status='READY'   → 注入 hostThreadParams.extraTools
                    └─ status='PENDING' → 不注入（终端类，待 57 号）
                          └─► hostThreadParams(summary, cwd, inventory, extraTools)
                                ├─ core 5 工具恒在（pfc_read_file / write / run_checks / git_status / git_diff）
                                └─ + 白名单解析后的配置工具
```

**安全边界**：
1. 只有 `host-tools-registry.js` 里 `status='READY'` 的工具可注入；`PENDING_HOST_SUPPORT` 的工具（codex_cli / zed_terminal / vscode_terminal）只可配置声明，**不会**注入到执行会话（没有真实执行器就不暴露无效工具）。
2. 核心 5 个 `pfc_*` 工具恒在，与配置无关；extraTools 与 core 合并后一次解析，**重复名自动去重**。
3. 别名兼容（`codex-cli`→`codex_cli`、`zed`→`zed_terminal`、`vscode`→`vscode_terminal`），未知名直接过滤。
4. 变更对**下一个新作业**生效，运行中作业不受影响（与 55 号同边界）。

## 六、结论与后续

56 号完成「**配置中心 → EXEC 真实执行**」的热插拔闭环：页面上 dev 阶段启用的工具会随配置装载进 host 会话（白名单保护）。剩余：
