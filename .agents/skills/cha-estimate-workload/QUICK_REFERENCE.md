# 前端工时估算 Skill 快速参考

## 🚀 快速开始

### 基本命令

```bash
# 命令触发（默认输出）
/cha-estimate-workload

# 指定输出目录
/cha-estimate-workload --output ./reports/

# 指定完整输出路径
/cha-estimate-workload -o D:\reports\工时报告.md

# 自然语言
估算工时
工时评估
需求拆解
```

## 📋 参数说明

| 参数 | 别名 | 说明 | 示例 |
|------|------|------|------|
| `--output` | `-o` | 输出路径 | `--output ./reports/` |

### 输出路径规则

- **默认**：需求文档同级目录
- **目录**：`--output ./reports/` → 在目录下生成默认文件名
- **文件**：`--output D:\报告.md` → 使用指定文件名
- **命名**：`工时估算_{项目名}_{版本号}_{日期}.md`

## 📊 总工时计算

```
功能开发工时 = ∑(基础工时 × 平台系数 + 附加工时)
功能自测工时 = 功能开发工时 × 25%
需求评审 = 2-8H (根据规模)
发布上线 = 2-4H
项目总工时 = 功能开发 + 自测 + 评审 + 上线
```

## 📐 版本号格式

### 标准格式

```
项目标识_主版本.次版本.修订号
```

### 示例

- ✅ `HJYY_QW_2.41.5`
- ✅ `HJHS_1.0.0`
- ❌ `2.41.5` (缺少标识)
- ❌ `HJYY_QW_v2.41.5` (不要 v)

### 解析规则

```
HJYY_QW_2.41.5短险服务
    ↓
项目标识: HJYY_QW
版本号: 2.41.5
完整版本: HJYY_QW_2.41.5
需求名称: 短险服务
```

## 💡 快速技巧

### 复杂度判断

- **XS**: 非常简单，1-2个字段
- **S**: 简单，3-5个字段/功能点
- **M**: 标准，5-10个字段/功能点
- **L**: 复杂，10+个字段/复杂逻辑
- **XL**: 极复杂，多模块/多系统集成

### 平台选择

- **单端**: H5 或小程序，系数 ×1.0
- **双端**: H5 + 小程序，分别估算
- **原生**: iOS/Android，系数 ×1.5
- **跨端**: Flutter/RN，系数 ×1.3

### 附加工时判断

```
✅ 需要添加附加工时:
- 集成微信SDK (+2H)
- 集成支付宝SDK (+2H)
- 使用自定义组件库 (+2H)
- 与其他团队联调 (+3H/个)

❌ 不需要添加:
- 使用公司内部组件
- 正常的前后端联调
- 标准的第三方库（如Axios）
```
