# 66 号：设计产物人工补录入口（65 门禁兜底）

> 状态：已完成并验收（verify-66 15 PASS / 0 FAIL + 浏览器实测通过）
> 日期：2026-09-19
> 前置：65 号设计产物门禁已交付（commit 05256f3）

## 一、目标

65 号门禁会阻断无产物需求的 confirm-design，但被阻断的需求**只能重跑 EXEC**，无法人工修正——门禁错误信息里写了"或人工补录后重试"却没有补录入口。66 号补齐这个兜底：平台内直接补录/编辑四类设计产物，补录记录与 EXEC 产物可区分（source 可追溯），且**补录绕不过门禁**（格式不达标仍被 65 拦截）。

## 二、本次改动

### 1. 后端

- `server/src/routes/agent.js`：新增 `PUT /api/agent/requirements/:reqId/design-artifacts`（owner 专属，非 owner 403）——调用 `design-artifact-service.register()`，source 固定 `{origin:'manual', by, at}`。
- `server/src/domain/design-artifact-service.js`：`listForReq()` 返回结构增加 `source` 字段（前端可区分 EXEC/人工来源）。
- `server/src/local/static.js`（顺带修复真实缺陷）：**静态资源无 Cache-Control**，浏览器启发式缓存导致更新前端后仍加载旧版 JS（本次实测发现）——index.html/local-config.js 加 `no-store`，original/*.js|css 加 `no-cache`。

### 2. 前端（design-artifacts-view.js / .css）

- **空态入口**：无产物时显示"可直接人工补录"四类按钮。
- **每块编辑**：四个产物块标题行加「编辑」按钮（按 kind 预填现有内容）。
- **补录弹窗**：产物类型选择 / 名称 / 内容 textarea / **格式即时提示**（与 65 门禁同标准：方案含背景+总体架构、时序图含 sequenceDiagram、流程图含 flowchart、原型含 html/input/button；缺什么标红提示"保存后确认门禁将拦截"）。
- **保存**：PUT 成功 → 自动关闭弹窗并刷新卡片（含 mermaid 重渲染）。
- **fence 剥离修复**：mermaid 渲染的 clean 逻辑改为整行剥离 ` ```flowchart / ```sequenceDiagram ` fence（此前 ` ```flowchart ` 类型词残留导致渲染失败，实测暴露）。

## 三、验证结果（verify-66-manual-entry.cjs）
