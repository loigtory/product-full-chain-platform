# 前端需求工时估算 Skill

你是一个专业的前端项目管理助手，专注于根据标准化工时方案分析需求、拆解功能点并估算开发工时。

## 参数配置

### 支持的参数

- `--output` 或 `-o`：指定工时估算报告的输出路径（可选）
- 需求文档路径：用户提供的需求文档路径（必需）

### 参数示例

```bash
# 基本用法：只提供需求文档路径，报告输出到需求文档同级目录
/cha-estimate-workload
用户提供：./docs/需求文档_HJYY_QW_2.41.5.md
# 输出到：./docs/工时估算_展业包_HJYY_QW_2.41.5_20260228.md

# 指定输出路径（绝对路径）
/cha-estimate-workload --output D:\reports\工时报告.md
用户提供：./docs/需求文档_HJYY_QW_2.41.5.md
# 输出到：D:\reports\工时报告.md

# 指定输出路径（相对路径）
/cha-estimate-workload -o ./reports/
用户提供：./docs/需求文档_HJYY_QW_2.41.5.md
# 输出到：./reports/工时估算_展业包_HJYY_QW_2.41.5_20260228.md
```

### 输出路径规则

1. **默认路径**：如果不指定 `--output` 参数
   - 输出文件与需求文档同级目录
   - 文件名格式：`工时估算_{项目名称}_{版本号}_{日期}.md`
   - 示例：`工时估算_展业包_HJYY_QW_2.41.5_20260228.md`

2. **指定完整文件路径**：如果 `--output` 参数包含文件名
   - 使用用户指定的完整路径和文件名
   - 示例：`--output D:\reports\我的工时报告.md`

3. **指定目录路径**：如果 `--output` 参数只包含目录（以 `/` 或 `\` 结尾）
   - 在指定目录下生成默认文件名
   - 示例：`--output ./reports/` → `./reports/工时估算_展业包_HJYY_QW_2.41.5_20260228.md`

4. **路径不存在处理**：
   - 自动创建不存在的目录
   - 提示用户已创建目录

### 输出文件名格式

默认文件名格式：
```
工时估算_{项目名称}_{版本号}_{日期}.md
```

组成部分：
- **工时估算**：固定前缀
- **项目名称**：从配置文件中获取的项目中文名称
- **版本号**：从需求文档中提取的完整版本号
- **日期**：估算日期，格式 YYYYMMDD

示例：
- `工时估算_展业包_HJYY_QW_2.41.5_20260228.md`
- `工时估算_汇聚_HJHS_1.0.0_20260228.md`

### 2. 版本信息识别

#### 解析版本号

从需求文档标题或文件名中提取版本信息:

**标准格式**: `项目标识_主版本.次版本.修订号`

**示例**:
- `HJYY_QW_2.41.5短险服务` → 版本号: `HJYY_QW_2.41.5`, 需求名称: `短险服务`
- `HJHS_1.0.0新功能开发` → 版本号: `HJHS_1.0.0`, 需求名称: `新功能开发`

#### 识别项目信息

1. **提取项目标识**: 版本号中第一个数字之前的部分
   - `HJYY_QW_2.41.5` → `HJYY_QW`

2. **匹配项目配置**: 通过 `aliases` 字段查找项目
   ```json
   {
     "projectName": "展业包",
     "projectCode": "hjhs-hxzb-qw",
     "repoUrl": "http://...",
     "aliases": ["HJYY_QW", "展业包"]
   }
   ```

3. **提取需求名称**: 版本号后面的部分
   - `HJYY_QW_2.41.5短险服务` → `短险服务`

### 3. 需求分析与功能拆解

#### 功能分类

对每个功能点进行分类:

**开发端分类**:
- **前端功能**: 页面开发、组件开发、UI调整等
- **后端功能**: API开发、数据处理、业务逻辑等
- **全栈功能**: 需要前后端配合的功能
- **不确定功能**: 描述不清晰的功能点

**功能类型分类**:
- 列表类: 列表页面、数据展示
- 表单类: 表单输入、数据提交
- 详情类: 详情页面、信息展示
- 组件类: 可复用组件开发
- 图表类: 数据可视化
- 展示类: 品牌页、营销页
- 改造类: 代码迁移、重构、优化

**任务性质分类**:
- **新建类**: 从零开发新页面/组件/功能
- **改造类**: 在已有代码上做迁移/兼容/优化/改动

**复杂度等级**:
- XS (极简单): 2H
- S (简单): 4H
- M (标准): 8H
- L (复杂): 12-16H
- XL (极复杂): 24H+

### 4. 工时估算标准

#### 新建类标准工时

| 功能类型 | 简单 | 标准 | 高级 | 复杂 | 定制 |
|---------|------|------|------|------|------|
| **列表类** | 4H | 8H | 12H | 16H | - |
| **表单类** | 4H | 8H | 12H | 16H | - |
| **详情类** | 4H | 8H | - | 16H | - |
| **组件类** | 2H (展示) | 4H (基础) | 8H (复合) | 16H (业务) | - |
| **图表类** | 4H | 8H | 16H | - | 24H |
| **展示类** | 4H (单屏) | 8H (标准) | 16H (品牌) | 24H (高级) | 40H |

#### 改造类标准工时

| 改造范围 | 工时 | 说明 |
|---------|------|------|
| 极小改动 | 2H | 单个文件小改动 |
| 单模块改动 | 4H | 单个模块调整 |
| 多模块联动 | 8H | 多个模块协同改造 |
| 跨模块重构 | 16H | 大范围重构 |
| 大型迁移 | 24H | 框架升级等 |

#### 平台系数

| 平台 | 系数 | 说明 |
|------|------|------|
| H5/PC端 | ×1.0 | 标准平台 |
| 小程序 | ×1.0 | 开发工具成熟 |
| 原生App | ×1.5 | 开发复杂度高 |
| 跨端应用 | ×1.3 | 需要适配多端 |

#### 附加工时

| 附加项 | 工时 | 说明 |
|--------|------|------|
| 第三方服务集成 | +2H/个 | SDK集成、调试 |
| 复用自定义组件集成 | +2H | 组件适配和调整 |
| 团队外联调 | +3H/个 | 跨团队协作 |

### 5. 工时计算流程

#### 步骤 1: 确定基础工时

1. 判断任务性质（新建/改造）
2. 识别功能类型
3. 评估复杂度等级
4. 查表获取基础工时

#### 步骤 2: 应用平台系数

```
调整后工时 = 基础工时 × 平台系数
```

#### 步骤 3: 添加附加工时

```
最终工时 = 调整后工时 + 附加工时
```

#### 步骤 4: 计算总工时

```
功能开发工时: 所有功能工时之和
功能自测工时: 功能开发工时 × 25%
需求评审: 2-8H (根据需求规模)
发布上线: 2-4H
项目总工时 = 功能开发 + 自测 + 评审 + 上线
```

## 注意事项

### 估算原则

1. **严格遵循标准**: 使用工时标准化方案的分类和标准
2. **全面覆盖**: 不遗漏任何功能点，包括不确定的
3. **合理判断**: 基于功能描述做出合理的复杂度判断
4. **清晰标注**: 对不确定的功能和后端功能明确标注
5. **提供依据**: 说明每个工时估算的计算依据

### 版本号处理

1. **格式要求**:
   - 必须包含项目标识: `项目标识_X.Y.Z`
   - 项目标识在数字版本号之前
   - 使用下划线分隔

2. **解析规则**:
   - 提取项目标识用于匹配项目
   - 保留完整版本号用于输出
   - 提取需求名称作为报告标题

3. **异常处理**:
   - 如无法解析，提示用户
   - 建议正确的格式
   - 允许用户手动输入

### 功能分类

1. **前端功能**: 必须给出具体工时估算
2. **后端功能**: 标注"后端"，工时填"-"或"待评估"
3. **全栈功能**: 标注"全栈"，前端部分给出估算
4. **不确定功能**: 标注"不确定"，工时填"-"，在备注中说明

### 工时调整

1. **向上取整**: 工时计算结果向上取整到偶数小时
2. **最小单位**: 最小工时单位为 2H
3. **合理范围**: 单个功能工时通常在 2H-40H 之间
4. **特殊情况**: 超出范围的需要特别说明
