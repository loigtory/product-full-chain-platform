# 13-M1 接口清单与开发说明（正式平台 · 单机闭环）

> 配套：《12-正式平台服务端设计蓝图》+ `m1-schema.sql`。M1 目标：后端 + 前端替换原型 localStorage 跑通全链路（单租户 + 开发账号，执行仍为模拟/占位，Bridge 接入在 M2）。
> 规范：REST JSON（`/api/*`）+ WebSocket（`/ws/*`）；鉴权 `Authorization: Bearer <jwt>`；错误统一 `{ error: { code, msg } }`；分页 `?offset=&limit=`（默认 20）。

---

|---|---|---|---|---|---|

## 八、事件触发点（服务端自动写 notices，对齐原型 `P.pushNotice`）

| 事件 | 触发接口 | kind |
|---|---|---|
| 作业计划被拒绝 | `plan-reject` | warn |
| 质量门未通过 | `quality-gates`（存在 fail） | warn |
| 发布审批待处理 | `POST /api/reqs/:id/releases` | info |
| 插件安装待复核 | `POST /api/caps`（来源插件市场） | info |
| 观察窗口到期 | 定时任务扫描 `releases` | info |

## 九、M1 开发顺序（后端）

1. 建库（`m1-schema.sql`）+ 认证（dev-login）→ 2. 需求域 CRUD + 阶段门控事务 → 3. 执行域（模拟 run/计划审批/质量门/回放）→ 4. 治理域（caps/绑定/审计/知识）→ 5. 发布域 + 通知 → 6. 前端把原型 `P.s.reqs` 读写替换为 API（保留交互与状态机校验）
7. 验收：以原型 6 组回归行为用例为基准，逐接口对照（见《12》第八节映射表）。

## 十、缺口与说明

- M1 不实现：SSO（dev 账号顶替）、Bridge 真实执行（模拟推进）、CI 回填（手工触发）、向量检索（keyword 顶替）、多租户数据隔离校验（schema 已预留）。
- `knowledge.embedding` 依赖 pgvector，M3 启用；M1 检索沿用原型 keyword 逻辑。
- 上传材料在 M1 落本地目录（无 OSS，既定边界），容量条 = 配额表。
