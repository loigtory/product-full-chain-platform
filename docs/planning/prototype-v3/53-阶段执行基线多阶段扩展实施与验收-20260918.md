# 53-阶段执行基线多阶段扩展实施与验收-20260918

> 承接：52 号待办第 3 项「多阶段基线：当前 UI 仅 dev 阶段；design/test 等阶段复用同一服务（stage 参数已支持），UI 化按需扩展」。
> 状态：**已实施，HTTP（design/test 各 9/9）+ 浏览器（design 冻结→复核→撤权全链路 + dev 回归）验收通过**。本轮改动**未提交 git**，待用户确认后统一提交。

## 一、背景与决策

- 52 号完成 dev 阶段执行基线（冻结/复核/撤权）UI 化，但 exec-bar 在前端硬编码 `stage === 'dev'`——design/test 阶段虽有作业（设计产物、测试命令），却无执行基线入口。
- 53 号目标：把阶段执行基线从 dev-only 扩展为**三阶段（design/dev/test）**：
  - 服务端无需改动：`stage-plan.js` 的 `STAGES = ['idea','req','design','dev','test','accept','release']` 天然支持全阶段，freeze 校验 `stage === req.stage`；
  - 前端把 exec-bar 显示条件从 `stage === 'dev'` 放宽到 `['design','dev','test'].includes(stage)`，并按阶段预置表单模板（design：docs/**、*.md + ls/cat；dev：src/**、package.json + node --version/npm test；test：test/**、src/**、package.json + npm test/node --test）；
  - 无文件作业的阶段（idea/req/accept/release）不显示执行基线（不硬凑）。

## 二、实施内容

### 2.1 前端补丁 `output/pfc-workbench-prototype/patch-multistage.cjs`（已应用，可复现）

**workbench.js**（行 ~786）：

```js
// 旧：stage === 'dev'
P.domainView?.pg() && ['design', 'dev', 'test'].includes(stage) ? (P.execBar ? P.execBar(r, stage) : '...') : ''
```

**domain-conversation.js**（C.install 注入）四处改动：

1. **refetchStagePlan 阶段感知**：`r.stage !== 'dev'` → `!['design','dev','test'].includes(r.stage)`；API `?stage=dev` → `?stage=' + r.stage`；`stageKey(r,'dev')` → `stageKey(r, r.stage)`；
2. **冻结表单 placeholder 按阶段预置**：工作区（设计产物目录/代码工程目录/测试工程目录）、允许文件（docs/**, *.md / src/**, package.json / test/**, src/**, package.json）、允许命令（ls, cat package.json / node --version, npm test / npm test, node --test）；
3. **4 个 remote actions（stage-freeze/review/revoke/refreeze）阶段化**：函数体开头插入 `const stage = d.stage || r.stage;`，替换体内 `stageKey(r,'dev')` → `stageKey(r, stage)`、`stage: 'dev'` → `stage`；
4. **execBar 内 btn 透传 stage**：`P.btn(action, label, { req: r.id, ...(data||{}) })` → `{ req: r.id, stage, ...(data||{}) }`（remote 才能拿到按钮所在阶段）。

**base.css**：无新增（52 号 exec-fields/exec-err/exec-review 样式已覆盖三阶段）。
