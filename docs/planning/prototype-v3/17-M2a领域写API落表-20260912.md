# 17-M2a 领域写 API 落表（服务端状态机转正）

> 定位：M1→M2 的架构分水岭——数据载体从「状态树快照（前端整树 PUT）」升级为「领域模型（服务端状态机/门控/审批/审计/事件）」；reqs 写端点全部 501→真实实现；runs 域计划审批硬门、质量门、回放、租约落地。
> 验证：`server\verify-server-m2.mjs` 19 用例全绿 + `verify-server.mjs`（M1 基线）18 用例全绿。
> 诚实标注：① 领域存储当前为**内存态**（结构对齐 m1-schema.sql 正式表，PG 适配在 M2b 存储层接入）；② 执行仍为**模拟推进**（M2b Bridge 驱动后转真实）；③ 前端动作层切领域 API 在 M2b（本轮后端先行，前端 api 模式仍走整树 PUT 兜底）。

---

## 一、架构变化

| | M1（状态树快照） | M2a（领域模型） |
|---|---|---|
| 数据载体 | `app_state` jsonb 整树 | reqs/versions/materials/questions/messages/runs/run_plans/quality_gates/replays/leases 领域集合 |
| 阶段门控 | 前端 P.advance 校验 | **服务端状态机强制**（advance 返回 409 + blockers） |
| 审批硬门 | 前端模拟 | **服务端强制**（plan 未批准 start → 409） |
| 审计/通知 | 前端事件 | 服务端写 audit + notices（13 号第八节触发点） |
| 数据源 | 前端工厂种子 | 领域 store **从状态树种子导入**（数据连续，前端切换不丢） |

## 二、新增/改造

```
server/src/
├── domain/
│   ├── state-machine.js   # 阶段机：按序推进 + 前置版本确认 + release→observe 发布硬门
│   ├── store.js           # 领域存储（内存态 Map，结构对齐正式表；种子导入）
│   └── service.js         # 领域服务：reqs 写 + runs + leases + 审计/通知
├── routes/reqs.js         # 改造：读切领域层；写端点全部真实实现（501 移除）
├── routes/runs.js         # 新增：计划审批硬门 + 模拟执行 + 质量门 + 回放
├── routes/leases.js       # 新增：acquire/handoff（原子冲突 409）
└── routes/notices.js      # 改造：领域存储为权威（事件触发点写入）
```

## 三、状态机门控（服务端强制）

```
idea → req → design → dev → test → accept → release → observe
  每条边规则：
  1. 只允许按序相邻推进（跳级/乱序 → 409 STAGE_BLOCKED）
  2. 当前阶段需先确认版本（confirm-artifact）——首尾阶段除外
  3. release → observe 额外硬门：需发布 SUCCEEDED
```

## 六、已知边界（诚实标注）

- **内存态领域存储**：重启丢失；结构对齐正式表，PG 适配在 M2b（store 是唯一出入口，领域逻辑与存储解耦）。
- **执行模拟**：start 一次性生成模拟行（同原型工厂风格）；真实 Bridge 驱动在 M2b。
- 前端 api 模式本轮**不切换**动作层（仍整树 PUT 兜底），M2b 逐个动作切领域 API。
- governance/release/projects 域写端点仍待 M2c。

## 七、下一步（M2b）

1. **Bridge 协议**：`/api/bridges/pair|heartbeat` + `/ws/bridge|web`（终端对话流实时推送——平台差异化核心）。
2. **前端动作层切领域 API**：create/advance/confirm/send 等 api 模式走领域端点，整树 PUT 降级为兜底。
3. **PG 存储适配**：领域 store 落正式表（连 DATABASE_URL 自动启用）。
