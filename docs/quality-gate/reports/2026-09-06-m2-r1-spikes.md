## 异常与返工

- App Server 首次取消用例在 turn 已终态后才调用 interrupt，正确失败为 `no active turn to interrupt`。根因是客户端等待 `turn/start` 结果后才中断。改为监听 `turn/started` 通知后立即中断，复测通过。
- Zed 的 CLI/应用调用均返回 exit 0，但独立进程未保持；根据已确认的不猜测原则，本次不宣称界面已打开或 ACP 已连接。

## 数据与清理

- App Server thread 已删除，线程 id 仅保留 16 位 SHA-256 摘要。
- 四个 Spike 的临时工作区均输出 `PFC_SPIKE_TEMP_CLEANED`。
- Windows 进程树用例证明测试父进程与子进程均已终止。未终止任何测试前已存在的 Codex 或 Zed 进程。
- 详细 JSON 仅保留在 gitignored 的 `.local/m2-spikes/20260906-r1/`，不进入版本库。

## 冻结决策与残余风险

- R1 可以实现真实 Codex App Server 只读 AgentRun，但取消时序必须使用 `turn/started` 通知。
- Bridge 命令不宣称 exactly-once；副作用边界不明时进入 `UNKNOWN` 并由人工处置。
- R1 对 Zed 只展示安装、CLI 能力与 ACP 配置键检测，连接与可见打开状态为 `UNVERIFIED`。M3 完成人工界面核对和 Web/Zed 交接。
- 标准 `pfc` schema migration 仍未授权；后续只能在可清理的 `codex_test_*` schema 做数据依赖验证。
