## 一、背景与决策

- 此前各阶段的 skill/tool/mcp 是**代码里的静态声明**（`server/src/agent/stage-capabilities.js`），前端"本阶段启用能力"面板实际读取不到任何真实能力（skills 恒为空），且**没有配置入口**——用户多轮追问「配置中心在哪」「每阶段选用的工具没看到」。
- 55 号目标：**配置即数据的热插拔能力中心**：
  - 每阶段（idea/req/design/dev/test/accept/release/observe 8 阶段）可独立配置 skill/tool/mcp；
  - 页面操作（勾选/新增/删除/优先级）→ 写 `stage_capabilities` 配置表 → worker 每次新作业按阶段读取装载，**无需改代码、无需重启**；
  - skill 选型多来源：**本机已装（local）/ GitHub 生态（github）/ 公司 ai-dev 市场（company）**，默认清单为 v2 定稿（用户已确认）。
- 关键设计决策：
  - **配置即数据**：不设 immutable 触发器（热插拔是设计意图）；UNIQUE(tenant_id,stage,kind,name) 保证幂等。
  - **写操作 owner 专属**（改全平台阶段配置影响所有作业）；读操作登录成员可读。
  - **worker 装载边界**：TEXT 作业按 `job.input.stage` 装载 `enabledSkills`；EXECUTE 作业走 host 模式固定 dynamicTools（硬编码 5 个 pfc 工具），**不受配置表影响**（EXEC 工具热插拔扩展需与 54 号冻结计划衔接设计，见四-3）。
  - **变更生效边界**：保存后对**下一个新作业**生效；运行中作业不受中途变更影响。

## 二、实施内容

### 2.1 迁移 009 `server/sql/m2c/009-stage-capabilities.sql`（新增）

```text
CREATE TABLE stage_capabilities (
  id uuid PRIMARY KEY,
  tenant_id uuid NOT NULL,
  stage text CHECK(stage IN ('idea','req','design','dev','test','accept','release','observe')),
  kind text CHECK(kind IN ('skill','tool','mcp')),
  name text CHECK(length BETWEEN 1 AND 200),
  source text DEFAULT 'local' CHECK(source IN ('local','github','company')),
  source_url text, description text,
  enabled boolean DEFAULT true,
  priority integer DEFAULT 100 CHECK(BETWEEN 1 AND 999),
  updated_by uuid REFERENCES members(tenant_id,id),
  updated_at timestamptz DEFAULT now(),
  UNIQUE(tenant_id,stage,kind,name)
);
CREATE INDEX stage_capabilities_scope_idx ON stage_capabilities(tenant_id,stage,kind,enabled,priority);
```

- `migrations.js`：registry 白名单 + 009 SQL push；assertReady 各 includes 数组加 '009' + 009 块检查（表存在 + 主键/外键合法）。

### 2.2 `server/src/agent/stage-capabilities-config.js`（新增，配置服务）

- `list(db, ctx)` / `forStage(db, ctx, stage)`：读（authorizeCommand 'stageCapability.read'）；
- `enabledSkillsForStage(db, tenantId, stage)`：worker 专用轻量读（启用 skill 名按 priority/name 排序）；
- `upsert(db, ctx, input)`：幂等写（ON CONFLICT DO UPDATE；owner 专属）；
- `remove(db, ctx, stage, kind, name)`：删除（owner 专属）；
- `setEnabled(db, ctx, stage, kind, name, enabled)`：启停（owner 专属）；
- 校验：stage/kind/source 白名单、name 1-200、priority 1-999、sourceUrl 1-1000。

### 2.3 `server/src/routes/agent.js`（修改，配置中心四路由）

### 3.4 排查记录（重要，避免复踩）

1. **migrate-55 报 MIGRATION_NOT_READY 的根因不是 009**：54 号收尾清数据时 DISABLE 的 6 个审计触发器（stage_plans_guard / agent_jobs_guard / agent_events_immutable / req_versions×3）**未恢复 ENABLE**，导致 assertReady('008') 失败。已全部恢复 `ENABLE TRIGGER`（`ALTER TABLE ... ENABLE TRIGGER <name>`）后再迁移即通过。
2. **profile.js 版本白名单不含 009**：`layout()` 只认 006/007/008 → 启动 5188（009）报 `LOCAL_VERSION_INVALID`；已把白名单扩为 `['006','007','008','009']`。`profile.json` 的 `targetVersion` 同步 008→009。
3. **Start-Process 不继承上一次 PowerShell 会话的 env**：每次 PowerShell 调用是全新进程；启动 5188 必须在**同一条命令**里设 `$env:PFC_*` 再 Start-Process，否则落到 storage=memory。
4. **PowerShell 内联长 JS 的引号陷阱**（延续）：本会话统一改用 Node 补丁脚本（`.local/patch-*.cjs`）做文件替换，规避 `"` 与 `$1` 被 PS 吞掉的问题。
5. **seed 后 verify 会改配置**：verify 脚本禁用 brainstorm + 新增/删除 mcp 占位，属测试副作用；验收后重跑 `seed-55-capabilities.cjs` 恢复默认清单（幂等 upsert）。
6. **前端路由挂载**：配置面板挂在 AgentRunsPage SubNav（view=capabilities）；GET 接口消费 `/api/agent/stage-capabilities`（agent 模块路由，非 v1 治理 API）。
