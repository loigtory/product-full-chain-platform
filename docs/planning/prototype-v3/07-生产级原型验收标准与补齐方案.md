## 1. 目标与方案选择

生产级原型应让人完整完成真实任务，对对象、版本、权限、失败和恢复给出一致结果。AI、解析、Shell、测试和发布可以采用明确标记的模拟结果；点击、归属、版本、迁移和读回不能是假成功。

| 方案                                         | 代价与效果                               | 建议                         |
| -------------------------------------------- | ---------------------------------------- | ---------------------------- |
| 继续增加入口，再补规则                       | 现有污染/覆盖/错绑会扩散到更多路径       | 不采用                       |
| 保留原版，先统一对象/草稿/动作，再补完整任务 | 复用现有视觉和流程，用明确回归逐步收口   | 推荐，待用户确认后实施       |
| 立即迁移React并接真实服务                    | 同时承担产品规则未定、组件迁移和集成风险 | 关键规则收口后按正式路线推进 |

正式平台仍采用React/Vite、Fastify、PostgreSQL/Kysely及本地Bridge。平台允许Shell、文件、Git、测试和预览，通过平台和Bridge受控执行；浏览器本身不直接运行命令。结果必须绑定所选电脑和作业，不能以另一在线设备或另一条运行结果代替。

## 2. 统一六类对象关系

| 对象           | 必须表达的身份和关联                                                     | 用户可观察的规则                                           |
| -------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 输入草稿       | requirementId/sessionId、阶段、正文、附件、引用、回复目标、revision      | 切换恢复各自草稿；保存失败可见；异步结果回原归属           |
| 文件资产和解析 | assetId/version/hash、原件、缩略/解析版本、归属、分类、允许用途、状态    | 接收不等于解析完成；原件和预览一致；失败可恢复             |
| 消息与回合     | messageId/turnId/parentMessageId、需求/会话、上下文快照、请求标识、状态  | 重发有历史关系；重复点击不重复发起；停止回答与停止作业独立 |
| 变更建议       | proposalId、来源message、目标artifact/version、完整差异、处理状态        | 点击哪张处理哪张；刷新可恢复；过期拒绝；采纳生成新版本     |
| 执行和证据     | runId、工作区/设备、版本快照、控制端、事件序列、文件/日志/证据           | 搜索、URL、卡片、终端、下载指向同次执行                    |
| 交付快照       | handoffVersion、commit/build、testRun、acceptance、target/approval、观测 | 批准绑定冻结清单；关键变更需重新评估；历史可重现           |

这是概念约束，不是新建正式接口。具体字段仍需对照contracts设计；不要把模拟stamp固化成正式发布授权依据，也不要新增第二套工程状态机。

## 3. 四批完善范围及退出条件

### 批次一：不丢数据、不串需求、不操作错对象

范围：G01、A03/A04/A05、D01/D02/D03、W01/W02、G03/G06。

- 导航与业务写分离，所有业务写统一校验revision；冲突保留本地草稿，提供重载/合并。
- 附件、引用、回复目标按需求/会话保存；发送和重试重新校验归属、权限、版本。
- 差异卡传proposalId，采纳/拒绝准确更新、立即保存和渲染；重复点击幂等、过期拒绝。
- 下载明确版本或文件；搜索明确runId；看历史时不隐式回退最新对象。
- Unit/AC以稳定ID建立显式关系，排序、改名、同名新增、删除均有规则。

退出：以上失败场景全部转PASS；双窗口创建/编辑/导航无数据丢失；既有11组模型与13组浏览器回归保持通过。

### 批次二：文件和对话从输入到输出完整可用

范围：A02/A06/A07/A08/A09、D04/D05、G02，以及文件/会话未展开的状态。

- 明确类型、单文件大小、数量和总量；待发送与已发送共用资产。支持预览、原图放大、原件下载、取消读取和重新选择。
- 读取中发送明确采用等待或持续异步更新策略；不能留下永远不更新的parsing副本。切换、移除、取消不改变原归属。
- PDF/Word/表格用结构化合成样例表现页、段落、sheet/范围；说明解析失败、截断、全文和不可用状态，不声称任意用户文档已真实解析。
- 引用可回原文；本轮参考与长期材料分开，已发送上下文绑定版本。刷新后原件丢失要明确提示重新关联。
- 重发进入完整回合，保留原消息/附件/引用关系；连续发送、停止、失败重试和刷新反馈一致。
- 展示完整Diff、逐项采纳/拒绝、具体下游影响；支持历史定位和跨阶段摘要。

退出：“Word+规则表+截图→指定引用范围→生成差异→部分采纳→下载确切版本”可走完；失败、刷新、切换、只读均有可恢复结果。

### 批次三：追踪、协作、执行和交付对齐

范围：G04/G05、多CAP/Unit、角色分工、执行面板及交付/观察。

- 材料影响逐项显示名称、版本、摘要、具体受影响对象和待处理数。
- CAP/Unit/AC/case/run/evidence显式关联；独立状态聚合为整体阻断。分工、角色撤销、待办、审计均能定位准确对象。
- 工作区选择设备/repo/branch，显示dirty状态、能力可用性、文件前后内容；日志、退出码、预览进程与run一致。
- 排队、占用、工具范围、超时、取消、重试、费用/时长预算有可见状态；Web/Zed控制转移和紧急停止有明确规则。
- 测试批次可下钻，缺陷保留发现/修复/复测证据。发布冻结开发/构建/测试/验收/目标清单，变化使批准失效。
- 发布/失败/回滚/观察/最终复盘独立留史，多次观测和后续事项有时间、来源和负责人。

退出：两CAP、多Unit、一次失败测试、返工及回滚的合成任务可走完；结论可追溯，未完成CAP/Unit不会被整体成功掩盖。

### 批次四：桌面体验和开发交接收口

范围：V02、长内容、关键键盘、错误反馈及文档/测试一致性。

- 附件/引用区限高、内部滚动或折叠，消息区保留可读空间；长文件名、多引用、长回复可处理。
- 1280/1440/1920宽度及720/900/960高度下验证代表页面、长表格/Diff/日志、空/加载/错误及弹窗。
- Tab、Enter/Shift+Enter、Esc、焦点返回、错误定位、只读反馈、处理中重复点击可用；移动端不在项目范围。
- 页面动作、实际对象、产品方案、架构、路线图、26 Unit和验收表一致；将关键场景纳入有断言测试，失败退出非零。

退出：P0/P1为零，P2修复或具名接受延后；代表任务通过；陈立完成产品及视觉接受后确定原型基线版本。

## 6. 实施确认、风险和交接要求

后续实施按项目生命周期记录范围和明确的方案确认。本稿不把分析请求解释为新一轮正式平台开发授权。需陈立确认的选择包括附件发送等待策略、草稿/原件留存、会话组织、角色分工、历史批次留存和执行预算，随具体界面样例确认。

建议实施范围限原版自有源码、原型验证和说明；先留用户更新版指纹与可恢复备份，先失败断言再最小修复。文件/会话/建议逻辑集中在较大的app.js，修改时做最小职责拆分，保持接口稳定；正式页面迁移继续采用packages/ui和/ui-kit。

采用单执行者顺序集成；共享状态和动作契约不拆并行写入。浏览器/服务结束关闭；确需保留预览则列PID、端口、目的和停止命令。修复当前错误无需新增依赖；新增解析组件再评估版本、许可、供应链、资源和回退。

原型存储升级要验证旧演示数据迁移。出现丢失/错绑时停止并恢复隔离副本，不能清空用户数据掩盖问题。附件数量/总量、日志、并发和预算均有界，未经测量不得宣称性能达标。

交接应有源版本清单、产品行为/状态矩阵、逻辑动作及字段、26 Unit映射、测试报告、产品/视觉接受、残余风险和真实接入事项。正式上线另需环境/负责人/回滚/smoke/观察窗口与授权。所有批次退出条件通过前不使用“最终版”“生产级完成”等结论。
