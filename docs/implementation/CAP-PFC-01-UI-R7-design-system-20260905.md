# CAP-PFC-01 UI-R7 平台设计系统实施检查点

> 记录时间：2026-09-05  
> 分类：System Iteration / strict  
> 设计确认：用户确认方案 B“建设 `@pfc/ui` 设计系统并迁移核心页面”  
> 责任人：代码评审=陈立；测试=陈立；安全=陈立

## 1. 目标与硬约束

- 吸收 `https://ai-dev.hzins.com/` 的字体层级、青蓝品牌语言、留白、筛选状态、列表反馈和轻量动效，形成产品全链路平台自己的 UI 元素模板。
- `packages/ui` 是设计令牌、基础组件和跨页面交互模式的唯一来源；`apps/web` 只组合业务页面。
- 后续新增视觉元素必须先进入元素目录，补齐默认、悬停、按下、焦点、禁用、加载和错误状态后再被业务页面引用。
- 自动门禁阻止业务 CSS 直接写颜色、字体、圆角、阴影和动效时长，避免页面随性发挥。

## 2. 参考吸收与非目标

| 参考特征                                  | 平台化结果                                               | 明确不照搬                           |
| ----------------------------------------- | -------------------------------------------------------- | ------------------------------------ |
| `Noto Sans SC / PingFang SC` 中文字体层级 | 本地系统字体栈与页面、区块、正文、标签、说明五级排版令牌 | 不加载外部字体资源                   |
| 青蓝品牌色与多语义色                      | 基础色 -> 语义色 -> 组件色三层令牌                       | 不使用大面积渐变或单一蓝色铺满页面   |
| 搜索、筛选胶囊和明确选中态                | SearchField、SegmentedControl、SelectField               | 不把所有文字做成胶囊                 |
| 内容卡片的悬停和方向提示                  | 仅用于指标、独立对象和空状态的受控 Surface               | 不把表格工作流改成卡片墙，不嵌套卡片 |
| 统一 200ms 左右反馈                       | 颜色、边框、阴影与位移的组件动效令牌                     | 不使用装饰性漂浮或持续动画           |
| 统计页的指标与筛选层级                    | OverviewStrip、FilterToolbar、DataTable 模式             | 不制造虚假指标或无业务意义图表       |

## 3. 设计系统结构

```text
packages/ui/src/
  tokens/
    primitives.css
    semantic.css
    components.css
    index.css
  components/
    Button.tsx
    SegmentedControl.tsx
    SearchField.tsx
    SelectField.tsx
    Surface.tsx
    index.ts
  index.ts
```

- 基础令牌：中性色、青蓝品牌色、语义色、4px 间距、字号、圆角、阴影、动效。
- 语义令牌：画布、表面、文字、边框、主操作、成功、提醒、危险、焦点。
- 组件令牌：按钮、输入框、分段控件、面板、表格行、导航、弹层。
- 元素目录：本地/测试可访问的 `/ui-kit`，不进入生产业务导航，不保存业务状态。

## 4. 页面迁移范围

- 应用壳：品牌、侧栏、顶栏、主导航和全局焦点。
- 需求工作台：范围筛选、搜索、视图切换、需求表格、空/错/加载状态、新建操作。
- 门禁中心：概览、当前/历史切换、组合筛选、数据表格、加载更多。
- 材料库：概览、组合筛选、数据表格、引用展开、影响处理入口。
- 详情内复杂领域面板保持业务结构不变，但共享颜色、排版、按钮、输入和弹层令牌。

## 5. 允许文案与交互边界

- 保留既有导航和业务文案：产品全链路、需求工作台、门禁中心、材料库、新建需求及既有字段/状态。
- `/ui-kit` 只增加开发验收需要的元素名称和状态名称，不向业务页面增加营销文案。
- 不改变路由、API、权限、领域状态机、数据库结构或本地体验数据。
- 不新增依赖，不执行外部写入、Git 提交/推送、部署或发布。

## 6. 测试数据、验收和治理

- 组件测试不使用业务数据；页面测试沿用 `CODEx_TEST_` 合成数据和既有 mock/本地 PostgreSQL 体验模式。
- 自动化覆盖组件状态、`aria-pressed`、`aria-busy`、键盘焦点、清除搜索、路由和核心页面交互。
- 治理脚本扫描 `apps/web/src`，禁止直接颜色、字体、圆角、阴影和毫秒级动效值。
- Edge/Playwright 验收 1280x720 与 1440x900；检查页面非空、控制台、首屏、长文本、焦点、筛选、详情进入与 reduced-motion。
- Quick/Core/Full 全部通过才形成工程完成结论；责任人已登记为陈立，G10-G12、真实集成和一个工作日观察仍按实际证据约束正式业务验收与发布。

## 7. 风险、回滚与过程

- 风险：全局 CSS 回归、组件迁移改变可访问名称、视觉快照受系统字体影响、过度卡片化降低信息密度。
- 控制：保持现有 DOM 语义和可见文案；表格继续作为核心容器；组件测试与 Edge 实拍同时验收；不依赖外部字体。
- 回滚：撤销 UI-R7 的 `packages/ui`、`apps/web`、测试、门禁与文档变更；无数据库和外部环境副作用。
- 单代理串行实施；不启动并行代理。临时浏览器和测试进程验收后关闭；用户要求保留的本地 Web/API/PostgreSQL 单独报告。
