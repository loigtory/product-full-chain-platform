## 1. 本轮范围

T1 只建立五个 Unit 共用的领域与持久化底座：

- 生命周期对象、`G0-G12` 阶段、Question、GateRun、MaterialImpact 状态与不可变记录。
- 公共规则 01～10 所需的纯领域校验、状态转换和领域错误。
- PostgreSQL 显式 migration、Kysely 数据库类型、repository 事务边界与 outbox。
- 确定性合成测试数据工厂，以及状态/属性测试和隔离 migration/repository 集成测试。

不进入 T2 的 ActorContext、对象级授权和跨 CAP adapter，不进入 T3～T7 的 API、SSE、页面、自动门禁执行或完整验收。不提交、不推送、不部署、不连接外部环境，不使用真实数据或并行 Agent。

## 2. 实施与责任边界

- 陈立继续作为产品负责人和首期研发负责人，并以本次消息批准 T1 本地实现。
- Codex 负责本轮编码、自动化测试以及代码/测试/安全自审；自审不能替代独立人审。
- 代码评审、测试和安全负责人现统一登记为陈立；独立人员不作为阻断项。T1 是否通过仍分别以代码评审、测试、安全、业务验收及发布证据为准。
- 任何需要改变已确认业务规则、权限语义、用户可见结果或 T2+ 契约的情况立即停止并回到设计确认。

## 3. 实现顺序与退出条件

1. 先用失败测试固定枚举、G0 完整性、Question 转换、GateRun 单次推进、旧基线结果和 outbox 脱敏约束。
2. 实现最小 domain/contracts，使状态和属性测试通过。
3. 先用失败的本地 PostgreSQL 测试固定表、约束、索引、事务和 outbox 原子性，再实现 migration/repository。
4. 运行目标测试、quick 和 core；full 继续按项目规则 fail closed。
5. 写入脱敏质量报告，记录 runId、createdIds、清理和残余风险。

T1 退出条件：domain 状态/属性测试通过；migration 可在隔离 schema 正向应用并清理；repository 写入当前对象、时间线和 outbox 同事务提交，故障时全部回滚；quick/core 通过；没有遗留项目测试、浏览器或开发服务器进程。

## 4. 测试数据设计

| 项目       | 设计                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| 数据源     | 仅 `packages/test-data` 生成的本地合成数据                                                                                |
| 标识       | `CODEx_TEST_` + runId；本轮运行时生成唯一 runId                                                                           |
| 正向场景   | G0 缺项/完整、同名不同 ID、固定来源、其他来源含说明、三种敏感等级、G0 到 G1 单次推进                                      |
| 状态场景   | Question 的 OPEN/ANSWERED/CONFIRMED/SUPERSEDED/DEFERRED；GateRun 的 IN_PROGRESS/PASS/BLOCK/WARN/UNKNOWN；GateCheck 的 N/A |
| 边界与负向 | 空名称/原始想法、其他来源空白说明、手工跳阶段、重复 PASS、row_version 冲突、旧 baseline 迟到结果                          |
| 数据库断言 | 当前 baseline 唯一、运行中 GateRun 唯一、stage advancement 唯一、历史追加写、outbox 与业务事务原子性                      |
| 权限组合   | T1 只保留 actor/owner 标识；对象级授权行为延后到 T2，不把未实现权限测试报为 PASS                                          |
| 隔离       | 每次数据库测试创建独立 `codex_test_*` schema，只访问 `pfc_local`，结束时删除该测试 schema                                 |
| createdIds | 由测试报告记录；不创建真实业务 ID                                                                                         |
| 清理       | `afterAll/finally` 删除隔离 schema；失败时报告残留 schema 名称，不删除非测试对象                                          |
| 敏感数据   | 不含凭据、客户数据、正文材料或真实日志；输出不打印 `DATABASE_URL`                                                         |

## 5. 风险与回滚

- T1 migration 仅在隔离测试 schema 验证，不对默认业务 schema 执行，因此本轮不产生待保留业务表或数据。
- 若 migration 或约束不满足已确认规则，保留失败输出并修改未提交源文件；不以手工 SQL 修补测试库。
- 若发现 T1 需要 T2 权限决策或 T3 API 行为才能闭合，标记为延后/阻断，不把临时默认值固化为业务事实。
- `full` 门禁、独立安全复核、业务验收、一个工作日观察、提交和发布继续 BLOCK。
