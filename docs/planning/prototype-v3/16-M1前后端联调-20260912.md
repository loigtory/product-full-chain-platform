## 二、联调时序（api 模式首屏）

```
index.html 加载（脚本顺序：data → data-layer → api-client → model → … → app）
  └─ app.js: P.render() → P.save()        （工厂种子渲染；save 触发 scheduleFlush 但被 hydrating 拦截）
  └─ app.js: PFCAPI.api.init()
        ├─ hydrate(): 无 token → devLogin（POST /api/auth/dev-login → 存 JWT）
        ├─ GET /api/state
        │    ├─ 有 state → P.s = 服务端状态（整树替换）→ render → true
        │    └─ 无 state → seed(): PUT /api/state（工厂种子）→ false
        └─ hydrating=false → scheduleFlush()
此后每次 P.save() → scheduleFlush（500ms 合并）→ flushNow: PUT /api/state 整树
```

## 三、关键防坑

1. **hydrate 期间禁 flush**（`hydrating` 标志）：否则启动时 P.save 触发的 flush 可能用工厂数据覆盖服务端已有状态。
2. **P.save 只在 api 模式触发同步**：PFCAPI 全局存在，若不加模式判断，local/mock 模式也会 fetch → file:// CORS 报错（已验证修复）。
3. **checkRevision api 模式短路**：api 模式服务端权威，镜像写入与 storageBase 不等会误判跨窗口冲突。
4. **401 自愈**：token 失效 → 清 token 重登 → 重试 hydrate。

## 六、已知边界（诚实标注）

- flush 为**整树 PUT**（幂等可靠）；`/api/batch` 增量语义预留 M2。
- 无 WS 实时推送：他端修改需重载页面（M1 单机够用；M2 事件流）。
- 服务端内存态重启丢失；PG 模式持久。
- 领域写 API（create/advanceStage 等）仍 501，M2 落正式表后替换状态树快照。
