# 15-M1 后端骨架（Node + Express + PostgreSQL）

> 定位：M1 单机闭环的另一半。按《13-M1接口清单》提供鉴权、状态树桥接、领域 API 骨架与契约端点，前端 api 模式的后端落点。
> 路径：`server/`（`npm start` 启动；`npm run verify` 跑 18 用例）。
> 诚实标注：M1 以**状态树快照（app_state 表）**为持久化载体；领域写接口（POST/PATCH）本期明确 501，由前端全量 PUT /api/state 承载，M2 落正式表（m1-schema.sql 28 表已就绪）。

---

## 一、目录结构

```
server/
├── package.json          # express / pg / jsonwebtoken / cors
├── .env.example          # PORT / DATABASE_URL / JWT_SECRET / PFC_DB
├── sql/m1-schema.sql     # 正式领域表（复制自 docs/planning/prototype-v3）
├── src/
│   ├── index.js          # 入口：中间件、路由挂载、健康检查、错误处理
│   ├── db.js             # 存储层：PG + 内存态降级 + app_state 桥接表
│   ├── auth.js           # dev-login 签发 JWT + 中间件 + 角色权限集
│   ├── contract.js       # 契约定义（与前端 PFCAPI.api.contract() 对齐）
│   └── routes/
│       ├── auth.js       # POST /api/auth/dev-login · GET /api/auth/me
│       ├── state.js      # GET/PUT/DELETE /api/state（状态树桥接）
│       ├── batch.js      # POST /api/batch（变更队列批量提交）
│       ├── reqs.js       # 需求域：list/get/messages 真实实现；写端点 501
│       ├── notices.js    # 通知域：list/mark-read/read-all（真实实现）
│       └── contract.js   # GET /api/contract（契约清单）
└── verify-server.mjs     # 18 用例验证（启动 → 全链路 → 关闭）
```

## 三、存储策略

| 层 | 设计 |
|---|---|
| 正式领域表 | `m1-schema.sql`（28 表，PostgreSQL 14+），连接成功即建表 |
| M1 桥接表 | `app_state(key, value jsonb, revision, updated_at)`——前端整棵状态树快照 |
| 降级 | 无 DATABASE_URL / 连接失败 → **内存态**（诚实标注：仅演示，重启丢失）；`PFC_DB=memory` 可强制 |
| 种子来源 | **前端原型工厂**（P.factory()）：后端首次返回 null，前端生成种子 PUT 提交——原型数据资产复用 |

## 五、下一步（联调顺序）

1. **前端 P.init 异步化**（14 号文档第五节第 1 步）：api 模式首屏 `GET /api/state` → 空则工厂种子 → `PUT /api/state`；此后 `flush()` 批量提交 `/api/batch`。← 前后端真正握手
2. 配置真实 PostgreSQL（`.env` 填 `DATABASE_URL`），领域表落库验证。
3. 领域写接口逐个落正式表（reqs 写 → runs → governance → release），替换状态树快照。
4. Bridge 协议端点（M2）。

## 六、已知边界（诚实标注）

- 内存态无持久化（重启丢失）；PG 模式重启保留。
- 领域写端点 M1 为 501（写路径走 state 全量提交），**不会静默假装成功**。
- 无速率限制/多租户校验（M1 单租户；schema 已预留 tenant_id）。
- JWT_SECRET 默认值仅开发用，正式必须替换。
