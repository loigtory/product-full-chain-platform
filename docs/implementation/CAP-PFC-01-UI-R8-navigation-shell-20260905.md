# CAP-PFC-01 UI-R8 导航与页面骨架设计

## 结论

- 分类：标准强度系统迭代，涉及用户可见导航、菜单、页面骨架和视觉规范。
- 确认时间：2026-09-05。
- 已确认方案：方案 B，全宽顶栏、模块一级导航、页面内二级菜单、居中工作区。
- 实施范围：`packages/ui` 共享元素、`apps/web` 页面组合、设计系统目录、自动化测试和本地浏览器验收。
- 明确不做：不修改 API、数据库、权限、生命周期状态机、业务数据或外部环境。

## 目标与非目标

### 目标

1. 移除固定左侧栏，建立全宽、稳定、可复用的全局顶栏。
2. 一级导航固定为“需求 / 门禁 / 材料”，通过下划线和模块色标识当前位置。
3. 页面二级菜单承载模块内视图：
   - 需求：全部需求 / 待我处理 / 阻断项。
   - 门禁：当前待办 / 历史记录。
   - 材料：全部材料 / 待确认影响。
4. 页面使用统一的标题区、上下文信息、搜索或主要动作区域以及内容容器。
5. 将导航、二级菜单、页面标题区、模块色沉淀到 `@pfc/ui`，业务页面只负责数据绑定和状态映射。

### 非目标

- 不复制参考站的品牌、文案或营销型页面结构。
- 不将运营表格改造成卡片墙，不新增虚构统计。
- 不引入外部字体、图片、运行时依赖或网络资源。
- 不为材料“待确认影响”扩展后端查询契约；当前版本只对已读取的真实材料结果进行客户端视图筛选。

## 视觉与交互规范

- 字体：继续使用本地中文无衬线字体栈，页面标题 28px，一级导航 15px，正文 14px，字间距固定为 0。
- 页面表面：主背景为白色；标题区使用冷调浅蓝表面；内容区以分隔线和留白组织，不叠套卡片。
- 模块识别色：需求蓝、门禁紫、材料青绿；橙色与红色仅用于关注、阻断等业务语义。
- 内容宽度：居中最大宽度，支持 1280、1440、1920 桌面视口；低于 1120px 保留现有兼容性提示。
- 键盘：导航使用原生按钮与 `aria-current`；二级菜单使用按下语义；焦点环和减少动态效果沿用全局规则。
- 真实数据：统计、更新时间、列表行继续来自现有 API；不得为了丰富页面增加演示数字。

## 组件与所有权

- `GlobalHeader`：平台品牌、一级导航、全局动作和账户信息。
- `PrimaryNav`：一级模块选择，必须具有 `aria-current="page"`。
- `SubNav`：模块内视图，必须具有 `aria-pressed`。
- `PageIntro`：上下文、标题、说明、模块色和可选操作区。
- `ModuleAccent`：需求、门禁、材料三类语义视觉入口。
- 业务页面仍可拥有列表布局、字段宽度和业务状态映射，但不能定义新的颜色、字体、圆角或阴影。

## 实施与版本退出条件

1. 先以组件测试固定可访问语义，再实现共享组件。
2. 先在 `/ui-kit` 更新完整页面骨架示例，浏览器对照参考站检查层级、密度、字体和颜色。
3. 将相同组件迁移到需求、门禁和材料页面，保留现有业务交互与路由。
4. 1280、1440、1920 三个视口无导航重叠、文本截断或内容遮挡。
5. `check:ui-design`、Quick、Core、Full 全部通过；若环境门禁失败，保留准确失败证据，不把部分通过称为完成。

## 测试数据、风险与回滚

- 单元测试使用已有 `CODEx_TEST_` 合成数据；浏览器验收只读本地体验数据库，不新增或修改业务数据。
- 主要风险：顶部空间不足、详情页标题层级退化、二级菜单与既有筛选状态不同步、材料客户端视图在分页场景只覆盖已加载结果。
- 回滚：恢复 UI-R7 的 App 页面组合、样式和 UI 组件导出即可；本迭代无数据库回滚、无外部数据清理。
- 未纳入当前版本：移动端、自适应侧栏、后端材料待确认专用查询、正式发布与生产观察。
