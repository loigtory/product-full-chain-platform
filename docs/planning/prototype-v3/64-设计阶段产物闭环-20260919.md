## 一、目标

把「设计」阶段从"对话产出 + 人工整理"升级为**真实闭环**：PM 在 design 阶段发起真实 EXEC 作业，Agent 在工作区 `design/` 目录产出四类设计产物（方案设计文档 / 时序图 / 流程图 / 可交互原型），平台自动收集、登记为**需求设计产物快照**（可追溯、带指纹），前端在「方案与设计图」面板渲染（Markdown 文档 + Mermaid 图 + iframe 原型）。

## 二、本次改动

### 1. 数据层（schema 011）

- 新建 `server/sql/m2c/011-design-artifacts.sql`：
  - `design_artifacts` 表：`id / tenant_id / req_id / public_id（DA-<uuid8>-<kind>）/ kind IN(design,sequence,flow,prototype) / name / content(≤1MB) / fingerprint(sha256 64hex) / source(jsonb) / created_by / created_at`
  - `UNIQUE(tenant_id, req_id, kind)`：同需求同 kind 只保留**最新快照**（天然版本覆盖）
  - FK → reqs / members；`id_counters.entity` CHECK 加 `design_artifacts`
- 迁移机制修复（两个隐蔽坑）：
  - `migrations.js` 全部 `includes(target)` 分支列表补 `'011'`（此前 registry('011') 只返回 001/002/011，003-010 全丢 → MIGRATION_NOT_READY）
  - `profile.js` layout 版本白名单补 `'011'`（此前 LOCAL_VERSION_INVALID）
- 迁移已应用：`migrate-m2c.mjs --target-version 011` → `applied:true`，checksum `509b6cf1…88b18`

### 2. 服务层

- 新增 `server/src/domain/design-artifact-service.js`：
  - `register()`：按 tenant+req+kind upsert 快照
  - `listForReq()`：按公共 reqId 返回 `{kind: {name, content, fingerprint, updatedAt}}`
  - `collectFromWorkspace()`：扫描工作区约定四文件（design/design.md→design、sequence.mmd→sequence、flow.mmd→flow、prototype.html→prototype），文件缺失/空白跳过，source 记 `{origin:'exec-workspace', jobId, file}`
- `worker.js`：`completeJob` 成功后 `kind==='EXECUTE' && job.input.stage==='design' && hostScope` → collectFromWorkspace（try/catch 静默，失败不阻断作业）
- 路由：`GET /api/agent/requirements/:reqId/design-artifacts`（走 access.current()）
- **EXEC 阶段泛化（修复）**：
  - `approval-service.js`：live 校验 `req.stage !== 'dev' || job.input.stage !== 'dev'` → 支持 `['design','dev','test']`；stageSnapshot 用 `job.input.stage`
  - `agent-approvals.js`：`job.input.stage !== 'dev'` → 支持三阶段
  - `agent-jobs.js`：版本白名单补 `'011'`（AGENT_SCHEMA_REQUIRED 修复）
  - `routes/agent.js`：阶段能力展示 `stage==='dev'` → 三阶段

### 3. 前端

- 新增 `output/pfc-workbench-prototype/original/design-artifacts-view.js`（+ `design-artifacts.css`）：
  - design 阶段自动注入「方案与设计图」卡片（`workbench.js` 注入点）
  - 方案文档：轻量 Markdown → HTML（标题/列表/表格/代码块）
  - 时序图/流程图：Mermaid 渲染（fence 前缀剥离修正，首行类型保留）
  - 原型：`<iframe sandbox="allow-scripts" srcdoc>` 离线交互
- Mermaid 本地化：下载 mermaid@10.9.1（3.3MB）→ `original/mermaid.min.js`
- `static.js` 资源正则修复：支持多段文件名（`mermaid.min.js` 此前 404）

## 五、验证方式与缺口

- 验证：verify-64 端到端（真实 EXEC→产物→API→落盘独立核对）+ 浏览器 DOM/JS 计数 + 回归 61/62/63
- 已知缺口（不影响本轮闭环）：
  - 原型 iframe 为 sandbox 隔离，主文档无法程序化读取其内部 DOM（用户可交互，自动化断言依赖 srcdoc 内容特征）
  - design_artifacts 为"同 kind 最新快照"语义，历史版本暂不保留（后续如需版本追溯可加表结构）
  - 设计产物与 artifact 组（AG）的关系尚未打通（AG-27 已有业务确认，design 待确认）
