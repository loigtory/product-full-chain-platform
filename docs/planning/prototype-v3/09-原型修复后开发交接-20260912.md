2026-09-12，原型 V0.4。本轮依据用户“继续解决问题”修复9月12日复核列出的缺陷，入口仍为 [原版 index.html](../../../output/pfc-workbench-prototype/index.html)。当前自动验证见 [修复报告](../../quality-gate/reports/PROTOTYPE-REMEDIATION-20260912.md)。本稿记录已经实现的交互规则及正式接入要求，优先于05、06、07中的历史实现状态。

## 当前可以据此开发的规则

| 环节       | 本版实际交互                                                                                                    | 正式开发必须承接的规则                                                                    |
| ---------- | --------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 本地保存   | 保存前核对已读存储快照；其他窗口更新后阻止旧窗口自动保存和业务修改；重载保留文字/编辑草稿                       | 服务端版本条件写、事务、冲突详情与合并；localStorage检测不能替代跨设备原子并发控制        |
| 文件输入   | 文件选择、拖拽、粘贴；整批固定需求；20件/消息、单件10MB、批次50MB；文本读取上限200KB                            | 服务端统一校验、归属与用途权限、上传进度、取消、限流、文件存储配额                        |
| 读取和恢复 | 读取中禁发；失败可重读原File；刷新打断读取后显示失败，可查看并重新选择原件                                      | 上传、原件、解析各自有状态和版本；异步结果按assetId/attempt回写，取消或过期结果不能覆盖   |
| 原件与全文 | 图片保存当前会话原图和缩略图；文本保存完整正文，预览最多5万字符；全文、原文件分别下载；重选已读原件核对SHA-256  | 原件进入对象存储，解析正文/分页独立保存；下载校验权限、版本及内容指纹；原件缺失不能标成功 |
| 二进制材料 | PDF/Word/Excel只接收原件并明确“尚未解析”；不再显示虚构页数/段落/工作表数量                                      | 真实解析服务及结构化页、段落、sheet范围；解析失败、部分成功和来源定位仍需接入             |
| 引用       | 选材料/产物后可排除；发送及重发重新校验当前需求、材料用途权限和版本；消息引用按messageId定位                    | 按会话/回合冻结引用版本及范围，撤权后禁止继续分析；材料版本历史持久化                     |
| 会话       | 一个需求内按阶段展示消息；失败/停止/刷新中断后重发进入新回合；parentMessageId、turnId、replyTo关联旧消息        | 请求幂等、流事件序号、取消确认、断线恢复、消息审计；重试不重复执行工具副作用              |
| 建议与差异 | 建议从持久化消息恢复；版本、需求、作业不匹配则拒绝；全部/勾选字段采纳都生成新版本；未勾选项本次不采纳，决定保留 | proposalId绑定基线与字段稳定ID；服务端原子采纳，影响分析及确认；重复、过期请求拒绝        |
| 关系追踪   | Unit显式保存acIds；重排不改变关系；关联编辑、分工/状态可刷新回显；测试按AC ID查询                               | 关系表及外键；删除影响预览、稳定改名、多CAP聚合、case/run/evidence明细关联                |
| 下载       | 画布下载所选versionId；工作区文件下载精确runId/path内容                                                         | 不按“最新”替代指定对象；真实文件/hash/权限/缺失状态与界面对象一致                         |
| 发布与交付 | 批准冻结产物全文、作业/Git、测试、验收、Unit/AC及目标；关键内容变化后禁止使用旧批准执行；历史包逐字节可重现     | 不可变清单/证据对象、签名与审批版本、幂等发布执行；正式运行及回滚结果单独留史             |
| 桌面布局   | 附件和引用区内部滚动；1280×720下15附件仍保留消息区和输入框；保留原三栏                                          | 1280/1440/1920代表宽度与关键键盘路径作为开发验收场景                                      |

同名同大小但内容不同的文件不能作为已读原件重新关联；应添加为新附件。读取首次中断且尚无指纹的旧文件，只能按名称/大小恢复，不能声称已证明历史内容一致。旧格式附件/引用草稿按其原所属需求迁移；不重置用户演示记录。早期只有版本编号而无完整内容的发布快照明确拒绝生成“冻结包”，不能用当前内容补造历史。

## 源码与验证入口

- original/model.js：状态、版本写保护、门禁、审批和冻结内容。
- original/attachments.js：文件资产、读取、恢复、引用选择与原件/全文预览。
- original/conversation.js：发送/重试/停止、引用来源、建议和字段差异。
- original/downloads.js：精确版本/文件下载和冻结交付包。
- original/app.js：路由、渲染协调和事件委派；各业务页及动作模块继续按原职责组织。

在仓库根目录使用项目Node执行：

```powershell
.tools/node-v24.20.0-win-x64/node.exe output/pfc-workbench-prototype/verify-prototype.mjs
```

该命令顺序运行独立静态检查、8项完整性检查、11项模型回归、46项问题/边界回归和13项原有主流程。检查前后核对17个加载文件指纹；截图、下载与日志保存在输出的临时证据目录。原型页面HTTP/HTTPS请求被阻断，不运行真实Shell或发布。

本轮原型静态检查声明浏览器全局并检查10个修改模块，14个加载脚本均语法检查；这是独立原型检查，不更改或替代项目Quick/Core/Full。项目Quick在lint阶段失败，历史原型/备份和浏览器脚本尚未纳入正确检查规则，后续工程恢复前需处理该仓库门禁问题。

## 后续方案与路线边界

本轮关闭具体复核缺陷，可以按上表指导对应能力的技术方案与开发用例；不能据此把07的所有生产级退出条件标为通过。仍需单独设计/验证的原型覆盖包括：多CAP整体编排与失败聚合、结构化二进制内容及页/段/sheet引用、完整跨阶段会话与长会话恢复、多设备控制租约及角色撤销、真实容量与费用、完整浏览器兼容性。PC之外的移动端不在项目范围。
