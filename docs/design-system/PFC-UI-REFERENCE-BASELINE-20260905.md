# PFC UI 参考基线

> 状态：已由产品负责人确认，进入 UI-R10 独立预览验证  
> 研究日期：2026-09-05  
> 范围：设计研究与平台映射，不包含业务 UI 实施  
> 参考来源：用户提供的“AI 原生开发工作台”公开页面

## 1. 结论

参考系统的品质不是来自单一颜色、圆角或首页效果，而是来自贯穿首页、列表、统计、详情和贡献看板的一套稳定视觉语法：品牌色负责识别，彩色负责分类和指标，白色与冷灰负责内容承载；页面先建立概览和方向，再提供筛选和高密度工作区；所有控件使用统一的形状、边框、图标和 200ms 左右反馈。

上一版 PFC 只吸收了横向导航、居中宽度和浅色背景，遗漏品牌、表面层级、组件状态、图标语言、内容模板与完整交互，因此不能称为参考设计对标。

## 2. 已采样证据

真实 Edge 浏览器已覆盖：

- 首页：品牌顶栏、动态网格 Hero、主搜索、八类彩色入口、精选内容和页脚。
- Skills 列表：标题与数量、搜索、排序、来源筛选、三列内容卡、分页。
- 分类页：页面标题、三列大型分类入口、图标与数量布局。
- 使用统计：页面标题、五个指标卡、内部/外部对比、组合筛选、搜索、数据表和微型趋势图。
- Skill 详情：面包屑、标题与标签、主命令区、左主内容与右侧信息栏、版本与关联内容。
- 贡献看板：主指标、热力图、排行榜、分级强调色和高密度名单。
- 交互状态：搜索焦点、回车搜索、查询条件进入 URL、卡片 hover、表格行 hover。

研究截图保存在忽略目录 `output/playwright/ai-dev-reference-study/`，不作为产品资产或发布内容。

## 3. 设计理念

### 3.1 品牌安静，内容鲜明

- 全局框架以白色和冷灰为主，避免整页被品牌色淹没。
- 慧择青只用于品牌、主操作、链接、焦点和当前状态。
- 蓝、橙、青、粉、绿、紫、天蓝、红只作为分类或指标编码，不进入普通正文和大面积工作区。
- 强调色必须表达模块、状态或数据含义，不能仅作装饰。

### 3.2 先定方向，再进入工作

操作型页面遵循以下阅读顺序：

1. 页面名称与一句话上下文。
2. 必要的概览指标或阶段摘要。
3. 聚合筛选、搜索和视图操作。
4. 高密度主工作区。
5. 详情、历史或辅助信息。

这与“标题下面直接放一张孤立表格”有本质区别。

### 3.3 表面层级代替粗重分割

- 页面背景保持白色或极浅冷灰。
- 相关内容进入 1px 冷灰边框的白色表面。
- 默认尽量无阴影；悬停、浮层和需要抬升的对象才使用阴影。
- 通过 16/24/32px 间距区分层级，不靠大色块或粗线切割页面。

### 3.4 每种内容使用对应模板

- 发现与分类：多列卡片网格。
- 运营与数据：概览指标 + 筛选面板 + 数据表。
- 长内容详情：主内容 + 辅助侧栏。
- 生命周期任务：阶段摘要 + 工作列表 + 可展开详情。
- 不把所有模块都做成表格，也不把所有内容都做成卡片。

### 3.5 交互状态属于视觉系统

- hover、focus、active、selected、disabled、loading、empty 和 error 都必须有模板。
- 搜索和筛选进入 URL，可深链并在返回后恢复。
- 颜色变化使用约 200ms 过渡；强调卡片可使用 300ms 阴影或轻微缩放。
- 焦点态使用品牌色边框和 3px 半透明 ring，不能只依赖浏览器默认样式。

## 4. 参考设计参数

以下数值来自浏览器计算样式，不是肉眼估算。

### 4.1 字体

```text
中文字体：Noto Sans SC, PingFang SC, Microsoft YaHei, system-ui
正文：16/24，常规 400
次级正文与控件：14/20
运营页 H1：30/36，700
首页品牌 H1：60/60，700，仅品牌首页使用
正文主色：#333333
正文次色：#666666
```

PFC 映射：PC 运营页面使用 30px 页面标题、20px 区块标题、16px 正文、14px 控件/表格、12px 辅助信息。不得在工作台使用 48-60px Hero 标题。

### 4.2 颜色

```text
brand-primary: #00A0E9
brand-primary-strong: #0078C8
brand-primary-soft: #E6F7FF
text-primary: #333333
text-secondary: #666666
border-default: #E8EDF2
surface-page: #FFFFFF
surface-muted: #F5F7FA
danger: #FF4D4F
```

参考分类强调色：

| 角色 | 起始色    | 结束色    | PFC 建议用途             |
| ---- | --------- | --------- | ------------------------ |
| 蓝   | `#3B82F6` | `#2563EB` | 需求/主流程              |
| 橙   | `#F97316` | `#EA580C` | 待处理/关注              |
| 青   | `#06B6D4` | `#0891B2` | 材料/数据                |
| 粉   | `#EC4899` | `#DB2777` | 暂不分配，避免装饰性使用 |
| 绿   | `#22C55E` | `#16A34A` | 通过/完成                |
| 紫   | `#A855F7` | `#9333EA` | 门禁/审计                |
| 天蓝 | `#0EA5E9` | `#0284C7` | 信息/洞察                |
| 红   | `#F43F5E` | `#E11D48` | 阻断/失败                |

PFC 不照搬八色墙。模块色只进入图标底、指标卡、轻标签、趋势和少量关键入口；正文表格仍保持中性。

### 4.3 网格、形状与层级

```text
顶栏：65px，white/70%，24px backdrop blur，1px 轻边框，shadow-sm
主容器：最大 1280px，左右 16px，页面顶部 32px
普通卡片：16px 圆角，1px 边框，20-24px 内边距
大型分类卡：20px 圆角，24px 内边距，约 300x148px
筛选面板：16px 圆角，16px 内边距
输入框：36px 高，10px 圆角
筛选项：32px 高，12px 圆角，水平内边距 12px
表格容器：16px 圆角，1px 边框，overflow hidden
表格行：约 45px，高密度但不拥挤
```

PFC 的卡片圆角上限仍遵守项目规范：运营组件优先 8px；只有指标/入口等需要明显对象感的元素可经模板确认使用更大圆角。参考站的 16/20px 不能无差别复制。

### 4.4 图标与动效

- 使用一致的 Lucide 线性图标，常规线宽 2px。
- 图标尺寸按 16/20/24/32px 四档，不混用填充和线性风格。
- 指标图标置于淡色圆角底，不让纯文字承担全部层级。
- 普通状态过渡 200ms；强调卡片 300ms。
- 表格 hover 使用极浅灰背景；卡片 hover 使用蓝色边框与 `shadow-lg`，不移动页面结构。

## 5. PFC 页面模板

### 5.1 全局框架

`AppHeader`：65px 半透明顶栏，左侧品牌，中央一级导航，右侧唯一主操作与账户。一级导航保持 3-5 项；模块内二级导航进入页面，不与一级导航竞争。

当前业务映射：

- 需求：全部需求、待我处理、阻断项。
- 门禁：当前待办、运行记录、规则视图。
- 材料：材料库、待确认影响、版本记录。
- 洞察仅在具备真实统计能力后加入，不创建空菜单。

### 5.2 需求工作台

```text
PageHeading
  页面图标 + 需求工作台 + 业务说明
LifecycleSummary
  总需求 / 待我处理 / 阻断 / 本周推进
FilterPanel
  范围筛选 | 搜索 | 视图 | 次要操作
DataPanel
  表头 | 需求行 | 状态与阶段 | 行操作 | 分页
```

只有在真实数据和处理动作存在时显示概览指标；不得为了“高级感”制造假数字。

### 5.3 详情工作区

```text
Breadcrumb
Title + status + owner + primary action
Context strip / stage progression
Main column: requirement content, decisions, acceptance, history
Side column: metadata, gate summary, material impact, audit
```

桌面端建议主辅比例约 2:1；辅助栏可 sticky，但不得形成嵌套滚动区。

### 5.4 门禁与材料

- 门禁中心：状态概览、阶段/结论筛选、运行列表、阻断原因侧栏。
- 材料库：类型与版本概览、影响筛选、材料列表、关联需求侧栏。
- 使用对应模块色建立识别，但共享同一页面骨架、控件尺寸和状态规则。

## 6. 组件模板清单

后续只允许通过 `packages/ui` 实现并由 `/ui-kit` 展示：

- `AppHeader`
- `PrimaryNav` / `ContextNav`
- `PageHeading`
- `MetricCard` / `MetricStrip`
- `FilterPanel` / `SegmentedFilter`
- `SearchField`
- `DataPanel` / `DataTable`
- `StatusBadge` / `ModuleBadge`
- `StageProgress`
- `DetailLayout` / `InfoPanel`
- `EmptyState` / `LoadingState` / `ErrorState`
- `Drawer` / `Dialog` / `Toast`

每个组件必须定义 default、hover、focus、active、selected、disabled、loading 和 error 中适用的状态，并使用 primitive -> semantic -> component 三层 token。

## 7. 禁止模式

- 不再使用单一蓝色覆盖导航、标题、按钮、链接和所有状态。
- 不使用整块浅蓝标题带制造层级。
- 不用大面积空白掩盖信息架构缺失。
- 不在用户主视图展示长技术 ID、actor ID 或内部键值。
- 不用只有边框的默认表格充当整页设计。
- 不复制参考站营销 Hero、彩色卡片墙或页脚到运营工作台。
- 不在业务页临时写颜色、字号、圆角、阴影和动效。
- 不以 Quick/Core/Full 通过代替视觉验收。

## 8. 视觉验收门槛

每次参考型改版先交付一个真实页面样板，并提供参考/实现并排截图。评分总计 100：

| 维度           | 分值 | 主要检查                             |
| -------------- | ---: | ------------------------------------ |
| 品牌与整体气质 |   15 | 主色、图标、表面是否形成一致识别     |
| 信息架构与层级 |   20 | 是否先概览再操作，主次是否清楚       |
| 字体与排版     |   15 | 字号、字重、行高、对齐和截断         |
| 颜色与表面     |   15 | 中性色、模块色、边框、阴影、圆角     |
| 组件与交互状态 |   15 | hover/focus/selected/loading/error   |
| 工作流效率     |   10 | 搜索、筛选、返回、URL 状态与批量操作 |
| 完整度与一致性 |   10 | 1280/1440/1920 和真实数据状态        |

进入页面迁移的最低标准：总分不低于 85，且任何单项不得低于该项满分的 70%；最后由用户完成视觉确认。

## 9. 工具与证据要求

- 必须使用真实浏览器采样，不以网页文字描述代替视觉证据。
- 必须读取关键元素计算样式，不能仅凭截图猜颜色和尺寸。
- 必须检查至少一个搜索/筛选、一个 hover、一个 keyboard focus 和一个详情跳转状态。
- 必须保存忽略目录中的研究截图，并在设计文档中记录证据边界。
- 所需工具不可用时，先判断是权限、安装缺失还是能力不足。权限问题走受控授权；安装问题完成来源、版本、许可证、脚本和锁文件影响审查后再请求安装授权；能力不足则停止该阶段并报告阻断。

本次发现 `ui-ux-pro-max` 本地包的 `scripts` 和 `data` 是失效路径指针，声明的检索脚本无法执行。该问题不影响本次基于真实站点的浏览器采样，但在修复或重新安装前，不得声称已运行该技能的设计推荐数据库。

## 10. 当前决策

- UI-R9 工程门禁结果仍然有效，但视觉结论撤回为“不通过”。
- 产品负责人已于 2026-09-05 确认本视觉基线，并确认 UI-R10 采用独立预览路由读取现有本地数据库数据。
- UI-R10 只允许调用现有 GET 接口，不提供新建、推进、修改或其他写入动作；正式需求工作台、门禁中心、材料库和 `/ui-kit` 暂不迁移。
- UI-R10 必须通过 1280、1440、1920 三档浏览器对照和用户视觉验收，才可提出后续正式页面迁移方案。
