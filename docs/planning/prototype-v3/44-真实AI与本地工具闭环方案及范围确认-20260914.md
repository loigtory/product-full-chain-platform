## 二、路线选择与技术边界

| 方案                                                               | 收益与代价                                                                                                     | 本文结论             |
| ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------- | -------------------- |
| A：本机 Codex App Server + 当前 Express 领域服务 + 本地执行 worker | 复用本机 Codex、已有 JSONL 传输和审批经验；对话、文件、命令共用运行身份。需核实 CLI 版本、账号、输出契约与权限 | 推荐，待确认         |
| B：直接模型 API + 自建工具执行器                                   | 模型供应商更独立；需另配凭据、模型选择、工具协议、计费与恢复控制，已有 Codex 工作区适配利用较少                | 保留备选，未展开实现 |

不迁回 `apps/web` / `apps/server`，保留最新 `index.html`、原生 JS、`server/` Express、PG 和 WS 主线。旧 React/Fastify 工程及正式 `pfc` schema 不参与这次切换。浏览器只能调用平台 HTTP/WS；Shell、文件、Git、Codex 均由本机 worker 在授权范围内执行。

推荐数据流：浏览器 → 现有身份/权限与领域 API → PG 作业/事件 → 本地 worker → Codex App Server / 固定测试进程 → 可信结果入库 → WS 增量通知与 API 读回。worker 与 Express 使用父子进程 IPC，不暴露额外远程 Bridge 端口。每个实例具有临时身份和所属 run，浏览器无权伪造 worker 结果。

本机 `codex --version` 为 **0.154.0**；[旧协议说明](../../../packages/codex-adapter/PROTOCOL.md)绑定 **0.153.4**。已有协议检查只验证旧生成文件与清单，不能证明当前 CLI 可互通。首项开发闸 A0 必须验证安装路径/二进制指纹、initialize、账号状态、可用模型及本包使用的事件/审批子集。版本不符或字段缺失则明确阻断，不自动升级、降级、安装 CLI 或复写生成协议文件。

官方文档说明 App Server 默认支持 stdio JSONL，使用 initialize/initialized、thread/start、turn/start 和通知事件；命令/文件审批由服务端请求并关联 thread/turn/item。本文据此设计接口，再以已安装 CLI 的实际响应核验；账号和模型可用性本轮尚未检查。[Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)

只读复用 `packages/codex-adapter/src/jsonl-rpc.ts`、事件归一化/脱敏和已有工作区隔离策略；新 worker 可通过根目录已安装的 `tsx` 加载所需 TS 模块，启动时校验依赖可用性。旧 product-work-turn 会话禁止 Shell/MCP/文件工具，旧 workspace-write 会话审批对象没有完整保留命令/cwd；因此不直接把旧 HTTP worker 或旧会话包装器整体接到当前平台。新审批封装必须保留原请求并验证实际 executable/argv/cwd/路径/网络范围。任何复用都要有当前主线集成证据。

## 三、D1–D8 实施内容与退出依据

### D1 · 连接状态与运行基础

新增服务器侧 AI 配置与本地 worker 生命周期模块。非敏感配置含 provider、CLI 路径/版本、模型 ID、启用状态和限额；私有配置保存在本次隔离根，个人配置在后续启用时另行确定。不得读取并复制 Codex token 文件、把凭据写入 PG/源码/浏览器或改变登录方式。使用既有 Codex 登录状态；未登录时展示实际原因，由本人完成登录，不代填凭据。

子实例启动前核对非敏感配置及运行能力，必须以该版本实际支持的实例级配置关闭本包未批准的 MCP、apps、hooks、网络工具与子代理，且不改全局设置。无法隔离继承能力或不能验证 Windows 工作区沙箱时，先阻断工具路径；不能仅靠提示词声称权限已受控。

页面区分未配置、待登录、协议不兼容、可对话、可执行、运行中、异常。真实模式失败不能回退为模拟成功；原演练入口保持明确的演练标识。只有协议、账号、指定目录权限与运行预检分别通过，才能报告对应能力可用。health 返回真实能力状态与 schema 版本，不把“CLI 存在”当作“AI 已接通”。

### D2 · 附件理解与输入溯源

复用原件上传、sha256、权限、版本、撤回规则；新增解析任务与片段记录。普通文本/Markdown/JSON/CSV/HTML 提取文本，HTML 不执行；PDF 提取文本及页码，DOCX 提取正文/表格文本，XLSX 提取工作表/行列；PNG/JPEG 使用当前模型确实支持的图片输入。GIF 的动画语义、扫描 PDF OCR、嵌入对象、公式重算不在首包支持范围，必须展示未支持或部分解析，不得静默当成完整理解。用户若要求首包覆盖 OCR，先调整本包依赖、费用与验收。

原件上限继续 10 MiB/文件、100 MiB 工作区；每次最多 10 份选定版本，解压上限 50 MiB/文件，提取上限 100 页 PDF / 20 个工作表 / 20,000 个非空单元格 / 200,000 字符；10 秒解析超时。超限显式显示被截断范围，由用户选择片段后再发模型。引用保存 materialId/versionId/hash/page/sheet/cell/segment；材料改版、撤权或需求切换后重新校验，不复用旧授权。

“内部可用于当前需求”与“允许发送给模型供应商”分别校验。发送前界面能看到此次材料/版本/片段及目的；运行包可一次批准同一范围内的连续调用，变更材料、目标或权限再补确认。受限材料、`.env`、凭据、`.git`、依赖目录和无关个人文件不进入上下文。材料中的命令或提示仅为内容，不能授予工具权限。

### D3 · 同一需求的真实对话与原型/PRD/AC 联产

复用 reqId/sessionId/消息与引用版本；新增 providerThreadId/turnId 映射及输入指纹。真实增量事件写入有序日志后才通知浏览器，最终文本由实际模型结果形成；刷新、WS 重连从序号续读，不重复发起模型请求。

用户可以先看可交互候选，再在同一对话完善 PRD/AC；不要求先完成全文 PRD。模型输出受 schema 校验的 message 和关联候选 bundle，原型字段、业务规则和 AC 通过 ruleId 关联，使用现有 proposal → 预览差异 → 采纳 → 业务/设计确认流程。无效 JSON、超限或断裂引用标为生成失败/待修复，最多一次明确计入限额的修复请求，不能用固定模板补齐并冒充 AI 成果。业务版本有变化时标为过期候选，由用户重建或逐项处理差异。

停止、超时、失联分别落 CANCELLED / TIMED_OUT / UNKNOWN；UNKNOWN 必须按 thread/turn 与本地执行事实核实，不自动重放可能有副作用的请求。已经采纳的版本不能被迟到事件覆盖。

### D4 · 能力装配与项目扫描

现有能力/版本/启停与绑定模型继续负责配置；worker 发现的运行时能力另记 provider、版本、可用性、权限和最后核验时间。首包提供 Codex 对话/结构化产物、本地文件读取/编辑、Shell、Git 只读扫描、固定测试执行器，以及本机已经存在且用户绑定的 Skill 的发现与装配。Skill 内容及版本纳入输入指纹；Skill 不授予超出 run 的权限。不自动安装第三方 Skill/MCP/插件或启用既有未批准的 MCP；通用 MCP 市场、任意远程连接不以“已登记”冒充可执行。

项目必须显式选择目录；只读扫描 Git HEAD、分支、脏文件、入口与测试命令元数据，排除秘密、`.git` 内容和依赖目录，记录扫描时间/指纹。路径经 realpath、祖先 reparse/junction、允许根与文件数校验。项目更新后计划失效。首轮开发验证只扫描本包生成的合成 Git 项目，不扫描用户其他项目；日常项目授权在后续启用包中列明。

### D5 · 真实本地执行与范围审批

计划冻结需求/产物组、项目基线、材料版本、Skill 版本、允许文件、命令及风险。Owner 可一次批准具体运行范围；已批准命令与等价操作无需每次打断，新增路径、网络、命令族或基线变化重新形成差异审批。审批关联 requestId/threadId/turnId/itemId/runId，过期、拒绝、重复响应均不能执行。

代码在本次拥有的独立工作区中修改，返回真实 diff 与 changed-file hash；不直接写本平台仓库或个人业务项目。执行前后检查允许文件、根路径、文件数/字节、链接和敏感路径。命令通过真实 argv/cwd 进入执行器；不能仅凭字符串前缀批准 PowerShell、cmd、Node 等任意解释器。Codex 执行权限仍由 App Server 沙箱与审批共同限制；固定自动测试由独立受控进程执行，禁止依赖模型自报。

首轮工具网络关闭，允许的模型服务通信与命令网络分开。禁止安装依赖、推送 Git、写系统配置、访问业务数据库、创建服务或执行部署。执行目录和预置依赖在发起 run 前确定。提供 stdout/stderr、真实退出码、耗时、文件差异、取消与进程树清理；未知外部效果必须核实，不能改成成功。

### D6 · 测试结果与交付证据回写

以提测基线和 AC 为输入生成测试候选，用户确认映射后执行。自动结果来源为 LOCAL_RUNNER，只能由拥有该 run 的 worker 提交；网页与公开 HTTP 结果入口不能自行声明此身份。记录命令指纹、源码/测试文件 hash、运行与套件 ID、退出码、解析后的用例结果、日志摘要及证据 hash。首包支持预置 Node 测试项目和 `node --test --test-reporter=tap` 结果；解析必须核对完整输出、用例数与退出码，不能只匹配“passed”。

零用例、缺失输出、被截断报告、非零退出码、过期基线、重复结果、伪造 worker 身份均不能标 PASS。AI 说“测试通过”只是一段对话；产品验收仍由 Owner 根据实际原型/代码行为完成。测试失败接入现有缺陷与回归记录，再回到同一个需求修复和重跑，不能新建无关联的演示需求代替。

### D7 · 持久化、恢复与运维兼容

新增显式 `007-ai-tools.sql`，不得改写 001–006。候选新增表：agent_sessions、agent_turns、agent_jobs、agent_events、agent_approvals、material_extractions、material_segments、project_scans、tool_executions、runner_evidence。均具备租户/需求/运行归属、输入版本与时间戳；事件唯一键(runId,sequence)，审批与执行幂等键不可重复生效。新增 result 来源通过 007 的显式约束变更接入，不能改旧 migration checksum。

领域写入与待发作业使用同一事务，worker 领取有租约和 owner identity；消息、任务和结果分别落库。重启后待执行可重新领取；已派发但完成情况未知的任务进入核验，绝不自动重发。领域服务处理业务决定，agent 模块处理 provider/进程，仓储处理 SQL；拆分目前较大的 conversation/execution 服务，架构闸保护责任边界。

运行时、迁移器、预检、备份、恢复目前多处固定 006，本包必须一起适配：007 新包可在隔离环境升级；006 备份仍可在其明确版本环境恢复；旧备份不伪装成 007。正在运行/审批中的任务不能被备份恢复后重发。停止写入、备份取证与隔离恢复继续校验数据库/原件/解析片段/运行证据的一致性。应用启动不自动迁移。

本次开发仅应用到下述隔离 schema；现有个人 `5432/pfc_local/pfc_workbench` 保持 006、5188 不重启。实现和真实联调全部通过后，再给出包含代码版本、007 迁移、备份、回滚、账号/模型与具体项目的个人启用包。不能只换代码连不兼容的库，也不以删库回退代替恢复方案。

本机查到 VS Code，未查到 Zed。推荐首包提供 VS Code 打开精确工作区/文件/diff，并保持 Web 控制与真实运行镜像；这不是 Zed 同会话双向接管。验证时仅允许打开本轮合成工作区，使用独立临时 user-data/extensions 目录并禁用扩展、记录自有进程后关闭，不接入已有个人编辑器窗口或安装插件。Zed/IDE 双向接管、任意 MCP、复杂任意 HTML 原型、远程 CI/发布及团队身份仍保留在全产品范围，首包不宣称完成这些能力。如陈立要求这些也进入本次交付，应在实施前扩充本包，不默认取消。
