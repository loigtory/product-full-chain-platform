# CAP-PFC-01 UI-R1～R4 前端体验优化检查点

> 记录时间：2026-09-05 09:52:06 +08:00  
> 分类：System Iteration / strict  
> 设计确认：用户于 2026-09-05 确认方案 A“明亮专业工作台”及 UI-R1～R4，并授权引入 `lucide-react`  
> 责任人：代码评审=陈立；测试=陈立；安全=陈立

## 1. 目标与非目标

- 重建 PC Web 的字体、色彩、间距、图标和信息层级，使需求列表与详情成为适合持续办公的专业工作台。
- 把筛选、搜索、视图切换、结果反馈、状态、下一步动作和异常恢复放进一致的交互体系。
- 详情首屏明确展示需求名称、当前阶段、责任人、下一步动作，并让 13 阶段进度区分已完成、当前、阻断和未来状态。
- 不修改 API、领域状态机、数据库、权限和外部集成语义；不扩展移动端业务范围；不 commit、push、发布或部署。

## 2. 已选设计与实现范围

1. 采用明亮、克制、流程导向的桌面工作台：208px 导航栏、64px 顶栏、36～40px 控件、约 52px 表格行、4/6/8px 圆角层级。
2. 使用本地系统中文字体栈；正文 14/22，辅助 12/18，区块标题 16/24，页面标题 20/28；仅使用 400/500/600 字重和等宽数字。
3. 使用语义令牌：主色 `#245BDB`、画布 `#F5F6F8`、正文 `#1F2329`、边框 `#DDE1E6`，成功/提醒/危险各自独立；避免单色化、重阴影和嵌套卡片。
4. `lucide-react@1.41.0` 用于导航、搜索、列表/阶段切换、返回、关闭、刷新、增删等操作图标；状态保留中文文字，不只靠颜色表达。
5. UI-R1 覆盖令牌、字体、图标、应用壳；UI-R2 覆盖工作项工具栏、表格和状态；UI-R3 覆盖详情、生命周期、面板、对话框与抽屉；UI-R4 覆盖浏览器、键盘、焦点、长文本和视觉验收。

## 3. 概念基准与适配说明

- `frontend-app-builder` 要求先生成完整 Image Gen 概念；当前会话未提供内置 `image_gen` 工具，且用户未授权需要 API Key 的 CLI 备用路径，因此不执行 CLI。
- 替代基准为：本文件确认的设计令牌与布局、现有页面截图、代码中的既有信息架构，以及最终 1280/1440/1920 Playwright 实拍。
- UI 文字和控件全部保持代码原生；不使用截图替代界面，不新增营销内容、虚假指标、额外产品区或装饰性视觉资产。
- `ui-ux-pro-max` 的本地 `scripts` 为失效指针，无法运行其设计系统检索脚本；本轮直接落实其可访问性、语义令牌、交互反馈、图标一致性和响应式检查清单。

## 4. 测试、验收与退出条件

- TDD：先增加中文状态、结果计数和生命周期状态测试并确认预期失败，再实施最小改动。
- 自动验证：受影响单测、Quick、Core、Full；Full 继续串行执行 PC E2E、权限、并发、恢复、安全、性能和依赖审计。
- 浏览器验收：Edge/Playwright Chromium 的 1280×800、1440×900、1920×1080；验证页面身份、非空、无框架错误、控制台健康、搜索/视图/详情/弹层交互、键盘焦点、长文本与 reduced-motion。
- 工程 PASS 不等于正式产品验收或发布就绪。责任人已登记为陈立；G10/G11/G12、真实集成和一个工作日观察仍按实际证据判断。

## 5. 风险、回滚与过程

- 主要风险：CSS 全局回归、中文状态破坏既有测试定位、图标造成无障碍名称变化、表格长文本溢出、13 阶段在 1280px 下拥挤。
- 控制：语义状态组件统一映射；图标设为装饰或提供 `aria-label`；保持既有按钮名称和 API 调用；三档桌面尺寸实拍；不改变写操作路径。
- 回滚范围仅限本次未提交的 `apps/web`、UI 测试、依赖清单和证据文档；不触碰数据库和外部环境。
- 本轮不使用并行代理。预期重做次数、失败门禁和视觉修正记录在最终质量报告中；保留用户明确要求持续运行的本地服务并报告 PID/端口。
