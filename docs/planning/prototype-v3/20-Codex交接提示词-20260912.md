## 四、本轮任务（M2b-2）

### 4.1 必改点（已探明事实，直接采用）

1. **修复 `original\ws-client.js` 的 run 查找 bug**：现在用 `P.s.runs.find(...)`，实际前端 run 挂在 **`P.s.reqs[reqId].runs`** 数组下（见 `model.js` P.startRun 内 `r.runs.push(run)`）。`job.line` / `run.status` 处理都要改为遍历 `P.s.reqs` 下所有 run 查找，或按 `P.s.reqs[run.reqId].runs` 定位。
2. **P.tick 跳过领域 run**：在 `model.js` 的 `P.tick()` 循环开头对打标 `_remote === true` 的 run `continue`——领域 run 由 WS 推送驱动，不能被本地模拟 tick（pct+8 / 生成模拟行）双写。
3. **动作分流**（`run-actions.js`）：
   - `A['start-run']`：api 模式下改为异步调用领域 API 三步——`POST /api/runs`（createRun，reqId 取当前需求 id）→ `POST /api/runs/:id/plan-approve` → `POST /api/runs/:id/start`；非 api 模式保持现有 `commit(() => P.startRun(...))` 原逻辑。
   - `A['reject-plan']`：api 模式下改为 createRun → `POST /api/runs/:id/plan-reject`（reason 必填，取弹窗 reject-reason 字段）；服务端留审计并推 warn 通知。
4. **领域 run 合并进前端**：领域 API 返回的 run（字段：id/reqId/status/operation/exitCode）需包装成前端渲染所需结构（qualityGates 五门待执行 / replay 快照 / lease / planApproved / budget / lines 初始行 / scope 等，参考 `model.js` P.startRun 第 914-980 行的骨架），push 进 `P.s.reqs[reqId].runs`，设置 `P.s.ui.runId = run.id`、`P.s.ui.panel = 'terminal'`，然后 `P.save(); P.render();`。
5. **run id 空间**：前端种子 run id 为 `R-1200+`（P.s.seq 起点 1200），领域新 run 为 `R-101+`（领域 S.seq.run 起点 101）——**不会冲突**，无需改名。
6. **Bridge 离线回退**：领域 `startRun` 已实现——有在线 Bridge 派发 job.start（实时推送），无则服务端回退模拟（生成模拟行并 SUCCEEDED）。前端无需处理两种模式差异，统一等 WS/回读。

### 4.2 建议验证路径

启动后端（内存态）→ 启动 `sim-bridge.mjs` → 浏览器打开原型并切到 API 模式（数据层徽标）→ 对话创建需求 → 确认 idea 版本 → 阶段推进到 dev → 发起作业 → 批准计划并执行 → **终端面板应实时滚动 sim-bridge 的对话流**（单元测试 passed → 迁移待审 → SUCCEEDED）。
