## 📖 简介

`cha-estimate-workload` 是一个专为前端项目设计的工时估算工具。它基于《前端开发工时标准化方案》，自动分析需求文档、拆解功能点、估算开发工时，生成规范的工时估算报告。

### 核心特性

- 🎯 **智能需求分析**：自动识别功能点和开发端
- 📊 **标准化估算**：基于工时标准方案精确估算
- 📝 **版本信息识别**：自动解析项目和版本信息
- 🚀 **报告自动生成**：输出规范的 Markdown 格式报告

## 📋 参数说明

### 支持的参数

| 参数 | 别名 | 说明 | 必需 | 示例 |
|------|------|------|------|------|
| `--output` | `-o` | 工时报告输出路径 | 否 | `--output ./reports/工时.md` |
| 需求文档路径 | 无 | 需求文档的文件路径 | 是 | `./docs/需求_HJYY_QW_2.41.5.md` |

### 输出路径规则

1. **默认路径**（不指定 `--output`）
   - 输出文件与需求文档同级目录
   - 文件名格式：`工时估算_{项目名称}_{版本号}_{日期}.md`
   - 示例：`./docs/工时估算_展业包_HJYY_QW_2.41.5_20260228.md`

2. **指定完整文件路径**
   - 使用用户指定的完整路径和文件名
   - 示例：`--output D:\reports\短险服务工时.md`

3. **指定目录路径**（以 `/` 或 `\` 结尾）
   - 在指定目录下生成默认文件名
   - 示例：`--output ./reports/` → `./reports/工时估算_展业包_HJYY_QW_2.41.5_20260228.md`

4. **自动创建目录**
   - 如果输出目录不存在，自动创建
   - 提示用户已创建目录

### 使用示例

```bash
# 默认输出（与需求文档同级）
/cha-estimate-workload
需求文档：./docs/需求_HJYY_QW_2.41.5.md
# 输出：./docs/工时估算_展业包_HJYY_QW_2.41.5_20260228.md

# 指定完整输出路径
/cha-estimate-workload --output D:\reports\短险服务工时评估.md
需求文档：./docs/需求_HJYY_QW_2.41.5.md
# 输出：D:\reports\短险服务工时评估.md

# 指定输出目录
/cha-estimate-workload -o ./reports/

# 输出：./reports/工时估算_展业包_HJYY_QW_2.41.5_20260228.md
```

## 🐛 常见问题

### Q: 版本号无法识别怎么办?

**A**: 检查版本号格式是否标准:
- ✅ 正确: `HJYY_QW_2.41.5`
- ❌ 错误: `2.41.5`（缺少项目标识）
- ❌ 错误: `HJYY_QW_v2.41.5`（不要加 v 前缀）

### Q: 项目无法匹配怎么办?

**A**: 检查配置文件:
1. 项目标识是否在 `aliases` 数组中
2. `projects-config.json` 格式是否正确
3. 添加新项目配置后重新执行

### Q: 工时估算偏差较大怎么办?

**A**: 分析偏差原因:
- 复杂度评估是否准确
- 是否遗漏了附加工时
- 平台系数是否正确应用
- 根据实际情况调整标准

### Q: 如何处理不确定的功能?

**A**: 在报告中标注:
- 开发端列填写"不确定"
- 工时列填写"-"
- 备注中说明不确定原因
- 建议与产品/后端确认

### Q: 后端功能如何处理?

**A**: 正确标注:
- 开发端列填写"后端"
- 工时列填写"-"或"待评估"
- 备注中说明"后端功能"
- 由后端团队单独评估
