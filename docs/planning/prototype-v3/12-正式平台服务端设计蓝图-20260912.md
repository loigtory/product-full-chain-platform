# 12-正式平台服务端设计蓝图（原型 → 生产置换）

> 定位：把 `output/pfc-workbench-prototype` 已验证的能力（8 阶段门控 / 质量门 / 计划审批 / 知识库 / 开放协议 / 通知流 / 审计等，共 14 项吸收项 + 原型 13 项基础能力）**映射为可实施的服务端设计**。原型为浏览器 localStorage 演示，本文给出生产置换项：数据库、Bridge 执行协议、LLM 网关、鉴权租户、通知服务、文件存储。
>
> 前置约束（既有边界，不推翻）：文件本地管理、无 OSS；部门内网工具规模（GB~TB 级）；单团队起，租户隔离预留；模型不自研，走 LLM 网关。
>
> 适用读者：产品经理（验收口径）、后端/前端开发（实现）、运维（部署）。

---

## 一、总体架构（三层）

| 层 | 组成 | 职责 | 与原型关系 |
|---|---|---|---|
| 客户端 Web | 现有原型 UI 演进（HTML/JS 单页 + 状态同步） | 对话工作台、阶段视图、治理中心、交付中心 | 原型 UI 直接演进；localStorage 换成 API + 本地状态缓存 |
| 服务端 | API 网关 / 元数据库 / LLM 网关 / 编排引擎 / 通知服务 / 文件索引 | 需求-版本-材料-执行-发布全链路状态机、权限、预算、审计、知识库 | 原型 `model.js` 的状态机与动作全部平移为服务端事务 |
| 本地 Bridge（执行设备） | 用户电脑上的轻量守护进程 | 配对注册、租约控制、执行 Agent（Zed/Codex/VS Code/任意终端）、Shell/文件/Git、终端流与快照回放 | 原型 `Bridge` 演示卡的正式实现 |

关键原则：

1. **原型状态机 = 服务端事务**：原型 `P.s.reqs` 每字段都有服务端表/列对应（见第二节），阶段推进、质量门、审批都是服务端幂等事务，客户端只提交意图。
2. **执行在本地、元数据在服务端**：代码改动/终端输出发生在 Bridge 所在电脑；服务端只收元数据（文件路径、diff 摘要、命令日志、退出码）与快照。
3. **能力目录驱动工具调用**：LLM 网关只允许调用"已登记 + 已复核 + 阶段绑定 + 未超预算"的能力，与原型能力目录/阶段绑定一致。

## 二、数据库 Schema（核心表）

按域组织，字段与原型状态字段一一对应；所有表含 `tenant_id`（租户隔离）与审计时间戳。

### 2.1 租户与身份

| 表 | 关键字段 | 说明 |
|---|---|---|
| `tenants` | id, name, plan, created_at | 单租户起，多租户预留 |
| `users` | id, tenant_id, name, email, source(SSO/SCIM), status | 身份源同步 |
| `memberships` | user_id, role(owner/executor/viewer), team_id | 对齐原型角色矩阵 |
| `roles_permissions` | role, action, allowed | 原型角色矩阵硬编码 → 数据化 |

### 2.2 产品需求域（对应 `reqs`）

| 表 | 关键字段 | 对应原型字段 |
|---|---|---|
| `reqs` | id, tenant_id, name, goal, scope, owner, stage, project_id, closed_at | `reqs[*]` |
| `req_versions` | id, req_id, stage, version, content, confirmed_by, confirmed_at, stale | `versions` / `confirmVersion` |
| `materials` | id, req_id, file_ref, name, content, allowed, status, sha256, size | `materials`（含附件容量条） |
| `questions` | id, req_id, q, answer, answered_by | `questions` |
| `messages` | id, req_id, turn_id, role, content, attachments, refs, status | `messages`（跨阶段会话保留） |
| `caps_units` | id, req_id, cap_id, unit_id, status, owner, deps | `caps` / `units` 多 CAP 编排 |

### 2.3 执行域（对应 `runs` / Bridge）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `projects` | id, name, path, branch, tech, source(new/existing), loaded_by | 本地项目加载（元数据，不存文件体） |
| `bridges` | id, device_name, status, last_seen, pair_code_hash | 设备注册与在线状态 |
| `leases` | id, bridge_id, run_id, controller(web/agent), state(active/lost/revoked), acquired_at | 单设备租约 |
| `runs` | id, req_id, project_id, status, step, pct, controller, budget, spent, exit_code | 对应 `run` |
| `run_plans` | id, run_id, plan, approved_by, approved_at, rejected_reason | 计划审批硬门留痕 |
| `quality_gates` | id, run_id, gate_id, name, status(pending/pass/fail), evidence_ref, ran_at | 五门客观质量门 |
| `replays` | id, run_id, step_no, label, snapshot_ref, ts | 沙箱快照回放 |
| `run_lines` | id, run_id, cls, text, ts | 终端流（增量追加） |

### 2.4 治理域（对应治理中心）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `caps` | id, name, type(skill/mcp/acp/terminal), protocol, endpoint, src, ver, desc, pending, perm, ico | 开放协议能力登记 |
| `cap_bindings` | stage, cap_id, enabled, tenant_id | 阶段默认绑定 |
| `audit_logs` | id, actor, req_id, action, detail, ts | 审计（对齐原型 `audit`，全量留存） |
| `budgets` | tenant_id, period, quota, used | 积分预算与消耗 |
| `team_policies` | id, parallel_limit, network_policy, scope_rules | 并行上限/网络关闭/范围白名单 |

### 2.5 知识域（对应知识库）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `knowledge` | id, title, type(复盘/组件规范/接口契约/踩坑/Playbook), content, source_req, tags, embedding | 全文检索（pg_trgm/ES）+ 向量召回（pgvector） |
| `knowledge_links` | req_id, knowledge_id, matched_by | 自动检索引用留痕 |

### 2.6 发布与通知域

| 表 | 关键字段 | 说明 |
|---|---|---|
| `releases` | id, req_id, target, scope, stamp, rollback, hours, status, expires_at, snapshot_json | 发布审批 + 快照冻结 + 过期 |
| `release_cicd` | id, release_id, status, steps_json, ran_at | CI/CD 流水线（对接 GitLab CI/Jenkins 回填） |
| `notices` | id, tenant_id, user_id, kind, title, req_id, read, ts | 通知流（服务端承载） |

## 三、Bridge 协议（本地执行设备 ↔ 服务端）

传输：HTTPS + WebSocket（wss）。所有消息 JSON，服务端签名校验。

### 3.1 配对与注册

1. 用户在 Bridge 输入服务端生成的**一次性配对码**（原型已演示 `P.pairCode`），Bridge 请求 `POST /api/bridges/pair`。
2. 服务端返回 `bridge_token`（JWT，含 device_id），后续请求携带。
3. Bridge 心跳 `POST /api/bridges/heartbeat`（30s），超时 3 次标记离线。

### 3.2 租约控制（对齐原型多设备租约）

- 每个 run 同一时刻**只有一个控制端**（Web 或 Agent 终端，如 Zed）。
- `POST /api/leases/acquire`（run_id, controller）→ 原子抢占；冲突返回当前持有者。
- `POST /api/leases/handoff`（run_id, to）→ 控制转移，记录进审计。
- 断连超时 → 租约状态 `lost`，页面提示"租约失效"（原型已验证该路径）。

### 3.3 任务执行

| 消息 | 方向 | 内容 |
|---|---|---|
| `job.plan` | 服务端→Bridge | 执行计划（范围、步骤、预算、网络策略） |
| `job.approve / reject` | 服务端→Bridge | 计划审批结果（硬门：未批准不执行） |
| `job.start` | 服务端→Bridge | 批准后下发执行指令 |
| `job.line` | Bridge→服务端 | 终端增量行（文本/类/时间），服务端落 `run_lines` 并推送 Web |
| `job.snapshot` | Bridge→服务端 | 步骤快照（文件路径/命令/摘要），落 `replays` |
| `job.done` | Bridge→服务端 | 退出码 + 汇总，触发质量门评估 |
| `job.cancel` | 双向 | 取消（对齐原型 CANCELLING → 保留输出） |

### 3.4 能力与权限边界（服务端强制）

- 执行前校验：cap 已登记 + 已复核 + 阶段绑定 + 租户预算充足。
- 范围白名单：仅允许读取/修改 `projects.path` 下文件；Git 只读（fetch/status/diff，禁 push 到生产分支）；默认网络关闭，白名单放行。
- 每次 Shell/文件/Git 调用写入审计，不可关闭。

### 3.5 重连与状态恢复

- Bridge 断线 → 本地继续执行但暂停新范围，服务端 `run.status=UNKNOWN`；重连后增量补 `run_lines`，页面"核验结果"确认终态（原型已验证）。

## 四、LLM 网关

### 4.1 模型路由

| 阶段 | 模型类型 | 理由 |
|---|---|---|
| 想法 / 需求 | 大上下文通用模型 | 长文档 + 材料 + 知识检索 |
| 设计 / 评审 | 推理增强模型 | 方案论证、影响评估 |
| 开发 | 代码模型（对齐 Zed/Codex 所接模型） | 代码生成与测试 |
| 测试 / 验收辅助 | 通用 + 规则引擎 | 断言、门禁客观化 |

### 4.2 上下文组装（每轮重建，全留痕）

```
系统提示（角色/边界/诚实标注）
+ 需求与当前阶段版本（req_versions 最新确认版）
+ 材料（allowed 且未过期的 materials + 附件引用）
+ 知识检索（knowledge 按关键词/向量 top-k，对齐原型自动检索）
+ 会话历史（跨阶段视图，40 条折叠）
+ 可调用能力清单（能力目录 → 阶段绑定 → 快照）
```

### 4.3 工具调用

- 统一协议层：Skill（原生内置）/ MCP（server 命令）/ ACP（agent 端点）/ 终端（Bridge 执行）——对齐原型能力目录与协议徽标。
- 调用前：白名单 + 参数 schema 校验 + 预算扣减；调用后：结果归档（`run_lines`/审计）+ 失败回退文本。
- 版本指纹：能力登记时锁版本，升级走"登记 → 复核 → 启用"，不影响运行中快照。

### 4.4 预算与并发

- 租户级积分池（对齐原型 `budget`），每次 LLM/工具调用扣减，耗尽后只读。
- 并行上限（对齐原型 limit 3）：服务端队列 + 优先级。

## 五、鉴权与租户

- **身份**：企业 SSO / SCIM 同步（原型 IAM 演示卡）；本地开发环境支持开发账号。
- **RBAC**：`roles_permissions` 数据化，对齐原型角色矩阵（负责人/执行者/只读）。
- **租户隔离**：全部表 `tenant_id` 行级过滤；能力/知识/审计按租户隔离；Bridge 设备归属租户。
- **安全**：JWT 短期 + 刷新；Bridge token 仅本设备；审计不可篡改（追加写 + 校验和）。

## 六、文件与存储（既定边界：本地管理，无 OSS）

| 项 | 设计 |
|---|---|
| 文件体 | 服务端本地目录（`/data/pfc/files/<tenant>/<sha256>`），上传即本地落盘 + 哈希去重（同材料只存一份） |
| 元数据 | 元数据库存路径 + SHA-256 + 大小 + 引用关系（对齐原型容量条 = 本地配额） |
| 备份 | 服务端目录定时快照任务（rsync/卷快照），归档至内网共享盘 |
| 跨设备 | Bridge 通过内网共享目录或 Bridge 拉取，不复制文件体到云 |
| 容量 | 配额表控制，超出提示（原型已验证 budget 耗尽路径） |

## 七、通知流服务端

- 事件源：计划拒绝 / 质量门失败 / 发布审批待处理 / 验收通过 / 插件安装 / 观察窗口到期（对齐原型 `P.pushNotice` 触发点）。
- 架构：服务端事件总线 → 通知服务 → 站内（WebSocket 推送）+ 邮件 + IM（飞书群，可经插件市场"飞书消息推送"扩展）。
- 未读计数与已读状态存 `notices` 表，Web 端轮询/推送同步（原型已演示铃铛角标交互）。

|---|---|---|

| 客观质量门 | `quality_gates` 表 + CI 回填 | 覆盖率等阈值可配置；失败阻断验收 |
| 知识库反哺 | `knowledge` + 自动检索 + 向量 | 复盘自动入库；新需求自动引用 |
| MCP/ACP 开放协议 | `caps` 协议层 + 统一调用 | 任意 MCP server/ACP agent 可登记接入 |
| 本地项目加载 | `projects` 元数据 + Bridge 扫描 | 现有系统迭代可加载真实目录 |
| 沙箱快照回放 | `replays` + `run_lines` | 执行可审计回放 |
| CI/CD | `release_cicd` + CI 平台回填 | 审批后执行、失败可重跑 |

| 插件市场 | 插件清单 + 安装即登记 | 安装→复核→装载闭环 |
| SSO/租户 | SSO/SCIM + tenant_id 行级 | 单点登录、租户数据隔离 |
| 文件本地管理 | 本地目录 + SHA-256 + 配额 | 无 OSS 依赖，备份可恢复 |

## 十、验证方式与缺口

- 验证：本蓝图每张表/协议与原型字段逐一对应（见第八节映射表）；原型 6 组回归（static/integrity/model/production/browser/scope7-12 用例）作为行为基线，正式实现以同一行为用例验收。
- 缺口（如实）：① 向量检索需选型（pgvector 或 ES）；② Bridge 守护进程需按平台打包（Windows 优先）；③ CI 平台对接需具体实例；④ 模型成本模型需实测校准；⑤ 文件备份策略需运维细化。以上均不影响 M1 启动。
