# CAP-PFC-01 UI-R10 需求工作台独立预览设计

> 分类：System Iteration Requirement / strict  
> 状态：工程验证完成，产品负责人视觉验收不通过，待重新设计  
> 确认方式：产品负责人在确认“独立预览页 + 真实本地数据库只读数据”后回复“同意”  
> 版本：UI-R10

## 1. 目标与非目标

目标：在 `/ui-preview/workbench` 提供一个可独立验收的 PC 工作台样板，使用已确认的 PFC 参考基线、统一设计 token 和现有本地 API 真实只读数据，覆盖概览、搜索筛选、表格/阶段视图、选中详情和完整异步状态。

非目标：不替换 `/` 正式工作台；不迁移门禁、材料或 `/ui-kit`；不新增业务状态、指标口径、API 或数据库字段；不执行创建、修改、推进、门禁运行、迁移或任何数据库写入；不部署或发布。

## 2. 方案选择

候选方案：

1. 直接改造正式工作台：复用最快，但会把尚未视觉验收的设计带入真实操作路径，回滚和对照成本高。
2. 独立预览并读取真实只读 API：保留真实数据密度和异常状态，同时与正式页面隔离，便于并排验收和整体回滚。
3. 静态假数据视觉稿：隔离最强，但无法验证真实中文长度、状态组合和数据库体验，已被产品负责人明确否定。

已选方案：方案 2。真实数据仅通过现有 `GET /api/v1/requirements` 和 `GET /api/v1/requirements/:id` 获取；预览组件不接收或调用任何 mutation API。

## 3. 页面与组件设计

页面阅读顺序：

1. 65px 半透明全局顶栏：平台品牌、需求/门禁/材料一级导航、只读预览标识、体验账号。
2. 页面标题区：需求工作台、业务说明、数据来源与更新时间，不使用大面积浅蓝 Hero。
3. 真实概览：当前列表、阻断、需关注、覆盖阶段；无数据时全部显示 0，不制造指标。
4. 聚合工具栏：全部/待我处理/阻断项、搜索、排序、表格/按阶段和刷新。
5. 主工作区：高密度需求表或阶段分组；选中行保持高亮。
6. 右侧只读详情栏：名称、想法、阶段轨迹、责任人、下一步和时间；关闭后焦点返回触发行。

共享模板先进入 `packages/ui`：指标卡/网格、工作面板、状态展示和右侧详情栏。业务页面只负责数据获取、筛选、排序、状态映射和路由状态。

## 4. 视觉约束

- 字体、品牌色、中性色、模块色、半径、阴影、间距和动效全部来自三层 token。
- 运营页标题 30/36；正文 16/24；控件和表格 14/20；辅助信息 12px。
- 主容器最大 1280px；1280、1440、1920 宽度均保持稳定列宽和无横向溢出。
- 只使用 Lucide 线性图标，统一 1.8-2px 线宽。
- 默认表面低阴影；hover、focus、selected、drawer 才提高层级。
- 不加入参考站营销 Hero、彩色卡片墙、虚构菜单、虚构数据或装饰性图片。

## 5. 状态与交互

- URL 保存 `scope`、`search`、`view`、`sort` 和 `selected`，刷新及返回可恢复。
- 搜索采用 React deferred value；筛选、排序和视图切换立即反馈。
- 请求切换时取消旧请求，避免旧响应覆盖新状态。
- 覆盖 default、hover、focus、active、selected、disabled、loading、empty 和 error。
- 选中表格行或阶段项后读取真实详情；关闭详情后恢复焦点。
- 刷新只重新发起 GET 请求；页面内不存在写入按钮和 mutation 调用。

## 6. 影响范围与版本退出标准

预计修改：`packages/ui` token、共享运营组件与测试；`apps/web` 独立预览路由、页面和样式；UI 单元/E2E 测试；设计与质量证据文档。

UI-R10 退出标准：

- 自动化证明预览路由只执行列表/详情读取，筛选搜索、排序、视图、选中与错误恢复有效。
- Quick、Core、Full 门禁均通过；若环境阻断必须明确记录，不得用部分结果代替。
- Playwright 在 1280、1440、1920 逐档验证无重叠、无溢出、无控制台错误，并完成搜索、筛选、视图、选中详情和关闭回焦。
- 按参考基线 100 分量表自评不低于 85，任何维度不低于 70%；最终仍须产品负责人视觉确认。

延期项：正式页面替换、门禁/材料迁移、移动端、生产部署、真实环境测试、业务写操作。

## 7. 测试数据、安全与回滚

数据源：现有本地 PostgreSQL 经现有 API 只读返回；不创建测试数据。单元/E2E 使用 `CODEx_TEST_` 合成数据与路由 mock，不含客户数据或凭据，测试结束不需要业务数据清理。

安全：检查页面不渲染技术内部键值，不发送授权头或 cookie 到非同源目标，不暴露数据库连接信息，不提供 mutation 入口。

回滚：删除独立预览路由、页面及新增共享模板即可；正式工作台和数据库没有变更。停止条件包括意外 POST/PATCH/DELETE、权限绕过、敏感数据渲染、旧响应覆盖新筛选或浏览器资源错误。

## 8. 协作、验收与进程

本轮不启用并行代理，避免共享 UI token 与页面同时修改造成耦合冲突。代码评审、测试和安全责任人现统一登记为陈立；本轮正式验收仍以视觉复核结论和发布证据为准，不再因人员登记阻断。

浏览器与测试进程在验证后关闭；用户要求持续体验的 Web、API、PostgreSQL 服务可保留，并在交付中报告 PID、端口、用途和停止命令。

发布与观察：本轮不发布。只有样板经产品负责人视觉验收后，才编制正式页面迁移、回滚、发布 smoke、观察窗口和监控方案。
