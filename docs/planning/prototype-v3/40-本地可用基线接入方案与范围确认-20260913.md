## 三、候选产品与技术规则 D1–D8

### D1：固定入口和空白起步

个人入口固定 `http://127.0.0.1:5188/`，同一Express进程服务原工作台、API和`/ws/web`。通过个人启动器注入不含秘密的`personal`运行标记，强制`PFC_DATA_MODE=api`、同源API；不能被URL参数、旧localStorage模式或旧token切回演示/其他服务。直接打开原index.html的local/mock演练保留原行为，明显区分于个人入口。

服务只提供index、其明确引用的JS/CSS和专用无秘密配置响应；静态文件不得以仓库根、整个output或original目录任意托管。拒绝目录枚举、编码穿越、绝对路径、点文件、备份/验证脚本/截图及原件路径。上传HTML按现有受控下载规则交付，不能成为同源可执行页面。源index依然唯一，不生成另一份长期维护的页面。

打开个人入口：检查服务/存储就绪→未登录时显示“打开本机工作台”→输入本机访问密钥→进入空工作台或恢复自己的记录。首次仅有一个工作空间和Owner，需求、聊天、材料及产物均从空开始，绝不导入local/mock记录或R1演练。空态提供“新建需求、添加材料”；后续按已有主动作连续承接阶段。

个人入口隐藏模式/演练/切换姓名入口，服务端仍独立拒绝绕过请求。账号显示陈立和“仅本机”，提供锁定/退出。新登录/错误状态复用base/guide既有字体、颜色和控件，只新增必要布局；原三栏密度不改，不触碰保留React的UI包。

### D2：单人身份与同源HTTP/WS

候选采用**本机访问密钥＋服务端会话**。初始化用Node crypto生成32随机字节密钥，原文只写`.local/pfc-workbench/access-key.txt`；服务端配置仅存盐和scrypt摘要。ACL先验证为当前Windows用户、SYSTEM及Administrators范围，不能收紧/验证则初始化失败，不以普通可读文件冒充受控凭据。ops-files仅以固定Windows系统工具、参数数组和已确权路径设置/核对ACL，不拼接Shell字符串或修改父目录权限。使用者在自己电脑打开该文件并填写登录框；不在聊天、CLI标准输出、日志、截图、URL、Git或浏览器存储展示密钥。密钥不等于姓名，首版不提供找回/远程登录。

新增个人模式专用接口：`POST /api/auth/local-session`验证密钥并建立会话，`DELETE /api/auth/local-session`退出并撤销当前会话；沿用`GET /api/auth/me`读真实成员状态。个人模式关闭`/dev-login`、Bearer旧token及`/ws/bridge`；未配置profile直接启动业务`pfc_workbench`必须拒绝，避免绕过启动器。既有memory和六个明确隔离PG回归模式保留原协议，不能把它们的dev-login暴露为个人业务入口。

Cookie为不透明随机会话ID，`HttpOnly; SameSite=Strict; Path=/`，仅host cookie、不设Domain、不持久保存；loopback HTTP下不伪称HTTPS或Secure。会话只在服务内存保存，最长8小时、空闲30分钟、最多4个；超过返回明确限额，退出或进程重启全部相关会话失效。WS ping不延长业务空闲时间；每次领域操作和推送继续核对现有成员权限。登录失败统一响应，最多5次/分钟，密码校验最多1并发；缓冲输入限4KiB，计数窗口有界且不按任意攻击者字段无限建Map。

个人模式强制Host为`127.0.0.1:5188`；HTTP若带Origin必须完全同源，null/跨源拒绝，变更请求必须同源Origin并使用JSON。未带Origin的GET仍须会话才可读业务；不信任Forwarded/X-Forwarded-*，不启用凭据CORS。WS升级前检查同源Origin/Host和Cookie会话，禁止query token。退出/失效即关闭所属WS；重连不能自动dev-login。登录、健康、错误和WS URL不输出秘密/私人目录，响应no-store，补nosniff、禁止iframe嵌入及no-referrer。

本方案保护浏览器跨源误访和未持有密钥的普通本机访问，不隔离同一Windows账号下的恶意程序或管理员，也不面向LAN/公网。团队账号、TLS及设备级身份由后续方案处理；这属于A选项适用范围，不能写成团队生产认证。

### D3：显式配置和首次初始化

候选业务目标唯一：`127.0.0.1:5432 / pfc_local / pfc_app_local / pfc_workbench`；业务原件唯一`.local/pfc-workbench-files`。配置目录`.local/pfc-workbench`保存无连接秘密的profile、users映射、访问密钥摘要与ACL受控密钥文件、启动/操作所有权记录；数据库连接只从已忽略`.env.local`的DATABASE_URL在进程内读取，个人工具拒绝继承其他PFC/PG目标覆盖。JWT_SECRET如兼容模块仍要求则独立随机生成到个人忽略配置，不用访问密钥替代，不输出。

新CLI `server/scripts/local-workbench.mjs`分发`preflight / initialize / start / status / stop / backup / restore-check`；每个子命令独立实现。参数只接配置profile或运行ID，不接SQL、任意命令、任意工作目录或不受控路径。脚本基于自身所在仓库解析绝对路径，拒绝符号链接/junction重定向；现有PFCPlatform junction只供PG工具处理中文路径，必须先验证最终仍在仓库。

`preflight`仅核对工具版本、依赖/配置键、端口、目标schema元数据、迁移checksum/就绪和本地路径元数据，不启动产品、不recover、不建配置/文件、不隐式升级。结果分`INITIALIZATION_REQUIRED / READY / BLOCKED`，附明确缺项及安全错误码。

`initialize`仅在未来业务启用包确认后可执行：二次预检空目标→取得操作锁→先在暂存目录生成/验证私密配置与ACL→第一事务CREATE SCHEMA并写固定ownership标记→调用现有迁移器自身事务应用001–006→第三事务创建唯一租户和Owner→原子完成文件配置→独立读回。现有migrate自管事务，不能未经改造假称这些阶段是同一数据库事务。工作空间候选名“陈立的工作空间”、账号名“陈立”，UUID初始化时随机产生并写回；无需求、材料或能力种子。不得改已有schema、旧`.env.local`、旧pfc/pfc_experience或系统角色。

初始化跨PG和文件没有分布式事务：必须记录非秘密attemptId、阶段和目标OID；故障后进入`INITIALIZATION_INCOMPLETE`，拒绝服务启动。重试先核对同一attempt和OID，再从已提交阶段继续；租户/成员UUID在暂存配置预先固定，同一事务核对已有记录，不能再造租户或覆盖未知文件；若无法证明归属则保留并停止。已完成重复initialize仅返回ALREADY_INITIALIZED，不重置密钥或数据。清除失败业务初始化需再给出具体目标评审，本包不提供自动DROP业务schema。

### D4：启动、停止和状态恢复

`start`固定5188、loopback，先核对完整profile/006/原件根，再获取跨进程工作空间锁，最后允许现有recover及启动监听。业务运行与backup/initialize使用同一目标的PG advisory锁及本地操作记录，锁在recover前取得；重复启动/操作并发明确BUSY。数据库锁用额外max1专用连接，原领域pool仍max2；不得无限等待。

CLI前台运行服务器并输出非秘密PID/端口/实例ID/源commit；不注册开机启动、服务、计划任务或防火墙。`status`核对实例记录、进程路径/开始时间和健康响应，拒绝把端口上任意服务算为本平台。`stop`只通知此实例：使用仓库内受控IPC与随机实例凭据完成优雅停止，不按端口杀未知PID；5秒未结束则报告残留，不擅自强杀。IPC不得成为任意Shell接口。

停止先拒新写入、关闭WS，最多5秒等待正在执行的领域事务，再关闭HTTP/DB；中断未核实写保留原commandId/UNKNOWN。启动恢复沿用已有会话/作业规则，既不再次执行发布，也不自动重试外部效果。数据库断开或文件失效显示不可用，失败不降级memory。前端会话失效保留当前未提交输入在本页内存、提示重新解锁，登录同一身份后读回再提交；不自动重放写命令，退出主动清空业务缓存/页面/WS。

### D5：数据库与附件成套备份

首版采用**停写备份**：用户先停止个人服务，backup取得同目标独占锁；确认实例已停止、文件无临时写入、006结构/校验和有效，再使用项目PG18.6的`pg_dump`自定义格式仅导出目标schema，复制原件，生成manifest。工具固定exe路径/argv数组、shell=false，数据库密码只传子进程环境，不出现在命令行或报告；不改001–006，不备份整个pfc_local。

manifest包括格式版本、源commit、schema/迁移版本与checksum、表清单/行数与规范化内容摘要、原件引用/大小/SHA256、创建时间、完成标记；含业务数据的manifest/dump/原件只留忽略目录，不入库。逐项验证数据库file_objects与原件一致，缺失/损坏/额外临时文件拒绝完成。运行中其他独立SQL工具仍可绕过应用锁，因此备份操作期禁止人工并发改这个schema；首版不承诺跨第三方写入的一致性。

写入`.local/pfc-workbench-backups/<backupId>.partial`，全部核验成功后同卷改名为完成包；失败保留partial与安全原因，不显示“备份完成”。单次超时120秒，总备份上限1GiB、默认最多7个完成包；容量不足先报错，由用户选择整理，不自动删除旧备份/partial。备份带本机ACL，不含访问密钥原文、JWT_SECRET或DATABASE_URL；恢复身份配置使用备份内无秘密users/tenant映射，凭据在恢复目标重新生成。

该目录与数据同盘，仅提供误操作/升级恢复能力，不能防整盘损坏。异盘备份目的地和保密要求未由用户指定，本包不擅自复制到外盘/云盘；后续需要再确认目标。恢复点为最近完成备份，操作提示实际时间，不承诺连续零丢失。

### D6：隔离恢复演练与升级回退

不对dump做SQL字符串替换以改schema名。`restore-check`用现有PG18.6 binaries在`.local/local-use-baseline-20260913/restore/<runId>`建立一次性cluster，绑定`127.0.0.1:5548`，数据库仍名pfc_local，在**另一PG实例**恢复原schema名。所有物理数据仍在仓库，沿已核实的现有junction访问；不新建Windows服务、用户或junction。
