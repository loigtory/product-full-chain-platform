## 已实现及其实际意义

1. 动态工具绑定独立观察到的 item、request、thread、turn、完整参数及调用身份；跨 turn、参数变化、重复请求冲突和未 dispatch 均关闭。固定 Codex 0.154.0 的实际动态读回已证明 callId 与 item.id 对应。
2. 文件工具在动作前验证当前 Owner/租户/需求/开发阶段、作业租约、取消、上下文与冻结方案；APPROVED/RUNNING 先提交，再次核验后执行。文件路径、预期 hash、内容字节数、数量和总容量均受限，拒绝穿越、ADS、设备路径、凭据目录、符号链接和硬链接；冲突回退保留非本轮改动。
3. 执行记录保存身份、路径、hash、状态和范围摘要，不把文件正文写入审计记录。异常效果标为 UNKNOWN，恢复不重放，未决/失败工具阻止作业伪报成功。超范围请求等待新方案，用户同意范围不会直接执行。
4. 新增需求范围内的审批/执行读回接口和“工具审批与记录”弹窗，支持 Owner 同意范围或拒绝。拒绝不再要求旧文件基线完全未变，因此已发生的合法写入不会阻止拒绝后续请求；同意仍保留原冻结检查。
5. 宿主模式单独启用动态工具分发所需 code_mode_host，code_mode、原生 Shell/unified_exec/patch、外部 MCP/apps/hooks/记忆等关闭，并读回有效配置。独立预算串行记账，失败与取消均计入。

**没有开放公共 EXEC 入口。** 真实模型文件验证走宿主 dispatcher + 实际隔离 PG；没有覆盖公开 HTTP → worker → 页面完整执行链。页面交互使用明确的合成响应，另有真实 PG/WebSocket TEXT 停止及刷新检查。二者不能合并声称已完成 EXEC 端到端验收。
