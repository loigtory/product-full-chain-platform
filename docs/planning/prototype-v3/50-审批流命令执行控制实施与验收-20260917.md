# 50-审批流命令执行控制实施与验收-20260917

> 承接：49 号「命令隔离实测结论与方案调整」（AppContainer 三边界失效 → 用户选定方案 1「审批流驱动的执行控制」）。
> 状态：**已实施，单元+集成+真实模型链验收全部通过**。

## 一、背景与决策

- 49 号实测结论：AppContainer SECURITY_CAPABILITIES 隔离在 Windows 26100 上静默失效（文件/写/网络全穿透）；Restricted Token 因非管理员不可改 D:\ 根/C:\Users ACL；Windows Sandbox/VM 需管理员。**操作系统级隔离在本机不可行**。
- 用户决策（2026-09-17）：采用**方案 1 审批流驱动的执行控制**，审批粒度折中：
  - 白名单低风险命令**自动放行**（node --test、git status/log/diff 等）；
  - 敏感命令**逐条审批/拒绝**（git push/commit、rm、curl 外发、npm install、工作区外写入、读密钥目录）；
  - **阶段基线**：每阶段冻结命令基线，基线外命令不自动执行（对齐 44 号「冻结计划」）。

## 二、实施内容

### 2.1 新增 `server/src/agent/command-runner.js` —— 审批流命令执行器

安全模型（五层）：

| 层 | 机制 | 实现 |
| --- | --- | --- |
| 1 命令形态 | argv 数组校验 | 非空、string、≤32 参数、禁 `\r\n\0` |
| 2 deny 优先 | 敏感命令规则先于 allowlist | 6 条规则（见下） |
| 3 allowlist | 冻结计划精确匹配 | `allowedCommands` 任一条 argv JSON 完全相等 |
| 4 工作区限定 | cwd 必须为授权工作区 | `checkedWorkspace`（44 号规范目录） |
| 5 超时终止 | 超时杀整棵进程树 | `taskkill /pid <pid> /T /F` |

**6 条 deny 规则**（即使被配置进计划也拒绝）：

1. `COMMAND_GIT_MUTATING_FORBIDDEN`：git 仅允许只读子命令（status/diff/log/show/rev-parse/ls-files/ls-tree/help/version），push/commit/reset/clean/checkout/merge 等一律拒绝；
2. `COMMAND_DESTRUCTIVE_FORBIDDEN`：rm/del/rd/rmdir/erase/format/cipher/remove-item 任何形式拒绝；
3. `COMMAND_NPM_NETWORK_FORBIDDEN`：npm install/i/add/update/ci/publish/pack/init/link/exec/x/create 拒绝（npm test/run 本地脚本可经 allowlist 放行）；
4. `COMMAND_GENERAL_EXEC_FORBIDDEN`：仅允许 node/git/npm 可执行文件名（含 pinned node 绝对路径），curl/wget/powershell/cmd/sh/python 等一律拒绝；
5. `COMMAND_ABSOLUTE_PATH_FORBIDDEN`：参数禁止盘符/UNC/家目录/根绝对路径（只允许工作区内相对路径）；
6. `COMMAND_SENSITIVE_PATH_FORBIDDEN`：参数禁止 .ssh/credentials/.env/secrets/tokens/.git/config。

**执行与审计**：
- `spawn` 于授权工作区，stdout/stderr 每流上限 1MB（超限截断并标记 `stdoutTruncated/stderrTruncated`）；
- 超时默认 300000ms（与 worker turn 超时一致），`taskkill /T /F` 终止进程树；
- 返回 `{ exitCode, timedOut, stdout, stderr, warnings }`；`warnings` 复用 `exec-control.auditCommands` 做输出命令行痕迹审计。

### 2.2 修改 `server/src/agent/approval-service.js` —— 命令工具接线

- 命令工具映射：`pfc_run_checks→node-test`、`pfc_git_status→git-status`、`pfc_git_diff→git-diff`（`test-runner.commandVector`）；
- 校验阶段（事务 1）：命令向量经 `command-runner.assertCommandAllowed`（deny 优先 + allowlist 精确匹配）——拒绝即落 `DENIED` 审批 + `agent_events` 审计，返回 `{ code, approvalId }` 给模型；
- 执行阶段：**事务外运行命令**（避免长命令持锁），结果以独立事务落 `tool_executions`（SUCCEEDED，含 command/exitCode/timedOut/stdoutBytes/stderrBytes/截断标记/warnings/scopeHash/contextHash）+ `agent_events`；
- 未知工具仍 `TOOL_NOT_ALLOWED`；文件读写路径（pfc_read_file/pfc_write_file）未改动。

### 2.3 修改 `server/src/agent/execution-policy.js` / `test-runner.js`

- capability 从 `supported:false / EXEC_APPROVAL_COVERAGE_UNVERIFIED` → **`supported:true / EXEC_COMMAND_CONTROLLED`**；
- `test-runner.commandCapability` 同步；`runCommand` 委托 `command-runner`；
- `worker.js` 的 `requireCapability()` 解锁（EXECUTE 作业可进入 host 模式）。

### 2.4 未改动确认

- `protocol.mjs` 仍拒绝 host 模式 `command/exec` RPC —— 命令**不由 codex 子进程执行**，统一由服务端审批流执行器执行（codex 只通过 pfc_* 工具请求）；
- 文件读写管控（scope-policy/exec-control）、冻结计划/基线/回滚、300s turn 超时、10s 心跳均未改动。

### 3.3 真实模型链验收 `server/verify-ai-tools-host-exec-command-real.mjs`（**5/5 PASS**，modelTurns=1，临时启停 PG）

真实调用 codex host 模式（gpt-6-astra，模型=gpt-6-astra，实例隔离 CONFIG_VERIFIED），模型自主完成"测试失败→读文件→修复→复测通过→汇报"全闭环：

| 断言 | 结果 |
| --- | --- |
| preflight：连接与工具配置验证通过 | PASS（instanceIsolation=CONFIG_VERIFIED，textIsolation 全 true） |
| 真实模型调用 pfc_run_checks ≥2 次 | PASS（5 次工具调用：run_checks→read×2→write→run_checks） |
| tool_executions 命令审计全 SUCCEEDED 且首败尾通过 | PASS（首条 exitCode=1，尾条 exitCode=0；命令为 pinned node `--test --test-reporter=tap`） |

**模型实际轨迹**（本次运行节选）：`pfc_run_checks`（TAP `6 == 5` 失败，exitCode 1）→ `pfc_read_file` ×2（sum.js / sum.test.js）→ `pfc_write_file`（以 read 返回的精确 sha256 作 expectedHash 修复）→ `pfc_run_checks`（`ok 1 - sum(2,3) === 5`，exitCode 0）→ 最终回复引用 `# pass 1`。全程命令由服务端 `command-runner` 执行（codex 仅请求，不自行执行命令）。

**验收过程修复的脚本问题（非平台缺陷）**：
1. tool_executions 的 `id` 为 UUID，`ORDER BY id` 无插入语义 → 改按 `created_at` 排序（首败尾通过断言此前偶发误报）；
2. 最终汇报断言原查 `messages` 表，但 TextConversation（conversation-provider）**不写 messages**（消息持久化属 worker 职责）→ 改为断言 `completion.text`（模型最终回复）；
3. 断言 ESM 源码改用真实 dynamic import（原 `new Function` 替换法对 `export function` 取不到导出）。

**验收环境收尾**：预算账本（`.local/ai-tools-host-exec-20260917/budget.json`）末条 SUCCEEDED（40s）；临时 schema 已清理（cleanup-test-schemas.cjs）；失败轮残留工作目录已删；PG 已恢复 Stopped（用户硬约束）。
