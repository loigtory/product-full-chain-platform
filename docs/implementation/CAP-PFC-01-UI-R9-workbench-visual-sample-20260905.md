# CAP-PFC-01 UI-R9 需求工作台视觉样板

## 迭代结论

- 分类：严格强度系统迭代，修改用户可见页面骨架、导航密度、排版、颜色与交互布局。
- 用户确认：2026-09-05，用户在 UI-R9 方案说明后回复“继续”。该授权仅覆盖需求工作台真实页面样板、共享紧凑变体、自动化测试与本地浏览器验收。
- 当前版本：UI-R8 的工程门禁通过，但用户视觉验收不通过；UI-R9 不沿用“完成”结论。
- 明确不做：不迁移门禁中心和材料库的页面内容，不修改 API、数据库、权限、状态机或真实数据，不提交、推送、部署或访问外部环境。

## 目标与非目标

### 目标

1. 需求工作台采用紧凑企业运营布局，不再使用大面积浅蓝标题横幅。
2. 顶栏、页面标题、范围筛选、搜索、视图切换和数据列表形成连续的垂直操作动线。
3. 首屏优先展示真实需求列表，降低品牌、环境说明和技术编号的视觉权重。
4. 吸收参考站的紧凑导航、清晰字体层级、白底灰阶、局部高饱和强调和稳定内容网格。
5. 将紧凑顶栏与紧凑页头实现为 `@pfc/ui` 显式变体；未确认前不替换其他业务页默认变体。

### 非目标

- 不复制参考站的营销 Hero、分类卡片、渐变背景或公开内容站结构。
- 不新增虚构指标、演示模块、静态列表或脱离 API 的原型数据。
- 不隐藏业务阻断、加载、错误、空状态和权限边界。
- 不引入外部字体、图片、前端依赖或网络资源。

## 已确认方案

采用“紧凑型企业工作台”方案：

- 顶栏：需求工作台启用 56px 紧凑变体；品牌、一级导航、主操作和账户保持一行。
- 内容网格：需求工作台最大宽度 1320px，按 8px 节奏控制间距。
- 页头：白底紧凑标题区，标题 24px；保留真实环境与 CAP 上下文，但不做装饰性 Hero。
- 工具栏：范围 Tab、搜索框、表格/阶段视图切换位于同一操作带。
- 列表：表头与行高收紧；需求名称是主要入口，完整技术编号仅保留为可发现提示，不再占据主要视觉行。
- 色彩：页面骨架使用白色和中性灰；蓝色仅用于当前导航、主操作、焦点和行级交互；红、黄、绿只表达业务状态。
- 字体：Windows 优先使用 Segoe UI Variable Text 与 Microsoft YaHei UI；不加载外部字体。

## 真实数据与交互边界

- 列表、条数、状态、更新时间和下一步继续来自现有 `RequirementsApi`。
- 搜索、范围筛选和视图切换继续写入 URL/sessionStorage 的现有状态，不新增持久化字段。
- 技术编号不从数据中删除；列表按钮通过 `title` 保留完整编号，详情页仍展示需求编号。
- 本轮不创建测试业务数据；单元与 E2E 继续使用 `CODEx_TEST_` 合成夹具。

## 验收标准

1. 需求工作台的 `GlobalHeader` 和 `PageIntro` 明确标记为 `compact`，其他页面仍使用默认变体。
2. 搜索、范围 Tab 和视图切换均位于 `.worklist-controls`。
3. 工作台最大宽度为 1320px，顶栏高度为 56px，页面标题为 24px。
4. 需求技术编号不再作为列表第二行可见文本，但可通过需求入口 `title` 读取。
5. 1280、1440、1920 三种 PC 视口无重叠、横向溢出或文本遮挡；首个数据行在 900px 高视口首屏内可见。
6. 搜索、范围切换、表格/阶段切换和打开需求详情均保持可操作。
7. `check:ui-design`、Quick、Core、Full 全部通过；浏览器截图与参考图至少核对导航、布局、字体、颜色、密度、状态和交互七项。

## 风险、回滚与后续

- 风险：紧凑密度可能降低长技术字段的可见性；通过原生 `title`、详情页和明确列宽保留可发现性。
- 风险：共享紧凑变体可能被其他页面误用；通过显式 `density` 属性和组件测试限制。
- 回滚：移除需求页的 `density="compact"` 与 UI-R9 工作台类名即可恢复 UI-R8；无数据库与外部数据回滚。
- 后续：仅在用户确认真实工作台视觉样板后，才允许把紧凑模板迁移到门禁中心、材料库和 `/ui-kit` 正式目录。
