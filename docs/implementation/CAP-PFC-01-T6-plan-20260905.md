# CAP-PFC-01 T6 材料影响、恢复与时间线实施检查点

> 记录时间：2026-09-05 07:02:00 +08:00  
> 分类：System Iteration / strict  
> 授权：用户授权 T4 后连续执行后续 Txx；本阶段仅执行本地 T6  
> 设计基线：`REQ-PFC-001 V0.7`、`CAP-PFC-01 V0.1/R4`、`G9-A DESIGN_CONFIRMED`

## 1. 目标与非目标

- 实现 `UNIT-PFC-01-02/05`、`AC-CAP-PFC01-02-07/08` 和 `05-01～06`：候选 baseline 影响登记、责任角色确认、切换/不影响、下游结果失效、分页时间线、SSE 重放及刷新恢复。
- 影响未确认时，当前 baseline、Requirement stage 和已有 GateRun 保持不变；确认命令在一个事务内完成切换、回退、失效、时间线、outbox 和幂等记录。
- 当前对象是业务权威；TimelineEvent/SSE 只通知变化并触发重读，不反向推导或覆盖 Requirement、Question、GateRun 和 baseline 当前状态。
- 本阶段不实现 T7 全量 UI/性能/安全硬化，不接真实 CAP-PFC-02～05，不执行默认 `pfc` migration，不 commit/push/merge/发布/部署。

## 2. 已选实现语义

1. 产品经理登记一个 `PENDING` 影响评估时创建下一版本 `CANDIDATE` baseline；同一 Requirement 同时最多一个 PENDING，重复请求按 actor/route/key 幂等读回。
2. 登记请求携带推荐最早受影响门禁和候选 baseline 的结构化来源、用途、敏感边界；不接收或广播材料正文。推荐/选择门禁均不得晚于当前阶段。
3. 只有拥有 `CONFIRM_MATERIAL_IMPACT` 对象权限且本人具备 `PRODUCT_OWNER` 或 `BUSINESS_OWNER` 对应角色的 actor 可确认；确认角色必须与 actor 当前角色一致。
4. `IMPACTS` 必须选择最早受影响门禁。事务将旧 baseline 改为 HISTORICAL、候选改为 CURRENT、Requirement 回到所选 stage，并把原 baseline 从该 stage 起的 GateRun 标为 INVALIDATED；旧 result/check/evidence 不改写。
5. `NO_IMPACT` 必须记录非空原因且不接受 selectedStage。事务仍形成新 CURRENT baseline 和历史关系，但 Requirement stage 不变，旧 GateRun 不失效；页面明确显示“不影响”和确认责任。
6. 切换前再次锁定 Requirement 与 assessment，复核 expected rowVersion、original baseline 仍为 current、assessment 仍为 PENDING；任一失败不产生部分切换。
7. TimelineEvent 使用持久化递增 sequence；REST 按 sequence 分页。SSE 按 Requirement 重新鉴权，并以 `Last-Event-ID` 重放；游标不可恢复时发送 `stream.reset-required`，客户端只执行全量权威重读。
8. 浏览器不缓存需求正文到 storage。只在 sessionStorage 保存工作台 scope/view/search；详情读取或实时恢复出现无权/未知时立即清除已渲染详情，再显示错误和重试/返回入口。

## 3. 接口与投影

- `POST /api/v1/requirements/{id}/material-impact-assessments`：要求 `Idempotency-Key`；创建 candidate baseline 和 PENDING assessment，不修改当前对象。
- `POST /api/v1/requirements/{id}/material-impact-assessments/{impactId}/confirmations`：要求 `Idempotency-Key` + Requirement `If-Match`；确认 IMPACTS/NO_IMPACT 并原子切换。
- `GET /api/v1/requirements/{id}/timeline?cursor=&limit=`：当前权限下按新到旧分页读取脱敏事件摘要。
- `GET /api/v1/requirements/{id}/events`：`text/event-stream` 重放；支持 `Last-Event-ID`，每次连接重新鉴权。
- Requirement detail 增加 baseline history、material impact 摘要；当前值仍由 Requirement/current baseline 和持久化 GateRun 派生。

## 5. 验证、风险与退出

- TDD 顺序：contracts/domain -> application/in-memory -> PostgreSQL/fault rollback -> Fastify/SSE -> React -> PC Playwright。
- Quick/Core 必须 PASS；数据库验证切换原子性、范围失效、NO_IMPACT 和并发；浏览器验证 PENDING、确认切换、时间线刷新、加载错误重试与权限撤销清屏。
- 重点风险：候选提前生效、错误 stage 失效、旧 PASS 静默改写、双确认、事务半写、SSE 泄露摘要、事件顺序覆盖权威值、撤权后缓存正文残留。
- 回滚仅反向编辑未提交 T6 源文件；不删除默认 schema 或非测试数据。
- 停止条件：必须改变已确认影响规则、需要真实材料/外部环境写入、无法保证单事务切换，或发现越权正文/SSE 泄露。
- 技术退出不等于正式验收。代码评审、测试和安全责任人均为陈立；T6 正式接受仍取决于各项结论本身，不因人员登记阻断。
