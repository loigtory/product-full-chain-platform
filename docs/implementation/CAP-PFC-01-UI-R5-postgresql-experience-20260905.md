# CAP-PFC-01 UI-R5 本地 PostgreSQL 全权限体验模式

## 迭代分类

- 类型：严格系统迭代。
- 原因：变更本地运行配置、权限入口、持久化 schema、确定性测试数据和用户可见标识。
- 当前版本：UI-R5。
- 目标：让产品负责人在 PC 工作台完整体验当前已实现的需求生命周期能力，所有操作真实写入本机 PostgreSQL，并在 API/页面重启后读回。

## 已确认方案与边界

- 用户于 2026-09-05 确认使用 `127.0.0.1:5432/pfc_local` 的独立 `pfc_experience` schema。
- 只允许创建、重建和写入 `pfc_experience`；不得变更 `pfc` 或其他 schema。
- 只允许持久化 `CODEx_TEST_EXPERIENCE_` 前缀的合成数据。
- 体验模式只允许在 `APP_ENV=local` 且显式开关开启时启动，普通模式继续失败关闭。
- 允许停止并重启当前本地 API 与前端；不得访问外部环境、远程数据库或 Git 远端。
- 跨 CAP 授权、材料证据和自动门禁执行使用本地体验适配器，不代表真实外部系统已接入。

## 方案设计

- 独立 schema：复用正式生命周期表结构与删除保护，通过显式 setup 命令重建；应用启动不自动迁移。
- 全权限参与者：固定合成参与者拥有当前合同定义的全部角色；服务端统一解析为该参与者，前端不信任客户端角色声明。
- 依赖适配：只在体验模式下返回可执行门禁、有效合成证据和允许动作；所有响应均标识为本地 fixture 来源。
- 标识工厂：体验模式新建的需求、问题、门禁、时间线、审计和幂等记录全部使用 `CODEx_TEST_EXPERIENCE_` 前缀。
- 用户提示：页面显示“本地数据库体验”和“全权限体验”，未建设的独立导航明确标记为“规划中”，避免误判为权限不足。

## 测试数据设计

- runId：固定 `EXPERIENCE_SEED_V1`；实时验收使用 `EXPERIENCE_LIVE_<timestamp>`。
- 数据来源：仅由 `packages/test-data` 的确定性工厂构造，不使用客户、生产或人员真实数据。
- 场景：G0 待补齐草稿、G0 可执行门禁需求、G3 含问题/历史门禁/材料影响的需求。
- 权限与状态：同一合成参与者覆盖产品经理、产品负责人、业务负责人、研发负责人、测试负责人、发布负责人和团队管理员角色。
- 边界与负向：非 local 环境禁止体验模式；非体验前缀拒绝种子写入；普通运行配置保持依赖不可用。
- 预期断言：schema 精确、数据库名精确、所有业务 ID 前缀精确、页面可创建和推进、刷新与服务重启后状态一致。
- 隔离：仅 `pfc_experience`；不得跨 schema 读取或写入业务表。
- 清理与保留：验收结束后重建为初始体验种子并保留，便于用户继续体验；后续重置必须再次运行显式 setup 命令。
- 敏感数据：不写入真实姓名、工号、凭据、连接串或业务材料；命令和报告不得打印数据库密码或完整 URL。

## 验收、风险与回滚

- 自动验收：单元/集成/PC 浏览器测试，加数据库计数、ID 前缀和重启后读回。
- 人工验收：用户通过本地地址体验；代码评审、测试和安全责任人均已登记为陈立，各项结论仍需引用实际证据。
- 风险：本地适配器可能让用户误认为外部授权或门禁已接入；通过显著环境标识和交付说明控制。
- 回滚：关闭 `PFC_EXPERIENCE_MODE` 并以普通命令启动；`pfc` schema 不受影响。删除 `pfc_experience` 需新的精确授权，不包含在普通回滚中。
- 当前版本退出标准：Quick/Core/Full 通过；体验 schema 读回通过；页面写入、刷新、API 重启后读回通过；服务地址与进程信息可交付。
- 延后项：门禁中心和材料库独立页面、真实跨 CAP 授权、真实材料服务、真实门禁执行、正式责任人验收、发布和观察窗口。
