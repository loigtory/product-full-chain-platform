## 三、方案选择和产品约定

推荐 A：保留现有代码，先用确定性回归修复 F1–F5，再用有界真实调用证明控制链；通过后继续 44 号剩余业务集成。优点是保留已完成成果、每个阻断都有可复核退出条件；代价是原先缺少批准信息的 EXEC 请求将被明确拒绝。

B：继续联产和更多阶段调用，最后统一修控制。可较早出现更多界面结果，但新增证据仍可能失真，且扩大不可控执行面，故不推荐。

用户已同意“先修复、后补齐”的方向；以下具体处理是本次建议，确认后整体连续执行，不再逐个文件或普通测试询问。

### A1 作业停止、恢复和并发

- 将生命周期收敛到独立 `job-control.js`；worker 负责调度，不再把终态补写当通用异常兜底。每个 worker 使用独立身份，完成写入校验租约和当前状态。
- 服务端按租户、需求及 `input.aiMessageId` 关联作业，事务提交后发送取消。006 使用版本能力判断，避免用不存在表的异常破坏事务。
- 已排队作业取消后不派发。运行作业先发中断；能确认进程停止才报告取消完成，无法确认则保持 UNKNOWN 并提供核验状态。命令超时记录 TIMED_OUT，丢失 worker 不自动重放已派发工作。
- 同一工作区同时仅一个写作业；不同需求且不同工作区可并行。本轮只在一个指定场景测试两个并行作业。

### A2 执行前授权和差异回收

- 保留现有范围表单，发送前明确展示工作区、文件、命令、有效期和基线。点击确认后，服务端从登录身份生成批准来源并冻结到作业输入；不信任客户端 `approvedBy`，也不默认 `**` 全文件放行。
- 复用 007 的 `agent_approvals` / `tool_executions`，增加小型仓储。实际工具请求必须绑定真实 thread/turn/item、scope hash、当前身份及作业；同一范围内的请求自动按已确认规则处理，只有越界需要新决定。
- 如需要人工决定，使用 `POST /api/agent/jobs/:jobId/approvals/:approvalId/decision`，body 仅 `{decision, scopeHash, expectedState, commandId}`；身份来自服务端，Owner 权限、租户/需求/作业归属、有效期、幂等性均校验。旧公开结果入口不能借此提交 worker 成功事实。
- 通过当前安装版本的 App Server 协议验证实际命令和文件审批，禁止任意解释器前缀批准。无法证明所有允许工具在执行前被控制，则此 EXEC 能力标 BLOCKED；不得悄悄退回 `approval_policy=never` 或仅提示词约束。此时仍完成不依赖真实 EXEC 的修复和测试，保留具体协议差异供对齐。
- 只读计划要求真实只读执行边界。写计划只操作本轮拥有的合成工作区；路径逐级检查 realpath、符号链接/junction、敏感路径、文件/字节上限。平台仓库和用户其他项目均不是执行目标。
- 所有退出路径统一采集差异。只回收本作业拥有且指纹未被第三方改变的文件；冲突保留证据并阻断，不能用整仓 checkout/clean 覆盖其他变更。无法证明副作用已恢复时不报“已回滚”。

### A3 备份版本兼容

- profile、启动环境、备份 manifest、恢复目标使用同一明确的迁移目标。兼容历史未写版本的 006 profile/manifest；新 007 包明确写版本及完整迁移指纹。
- 源库版本不符、manifest 被篡改或未知版本均拒绝；不将 `assertReady` 改成“只要不少于 006 就通过”。
- 先验证隔离的 006 和 007 合成源、损坏包、007 作业/事件关联数据和文件摘要恢复。个人 5188 的升级启动、冷备份及恢复演练是后续运行操作，须对实际目标及停机窗口另行确认。

### A4 连续上下文

- 前端传来源标识/版本和明确的用户附言，服务端按当前需求回读。旧接口携带的自由文本最多作为“用户提供的补充”，不能成为确认事实。
- 未确认 AI 输出可以供探索，但标为候选；只有既有确认记录可作为开发准入。材料和产物改版、撤权时上下文重建，过期执行范围失效。
- TEXT 和 EXEC 使用同一份服务端上下文快照并记录 hash。最多包含 7 个前序阶段，保留 release → observe；单段上限 30000 字符、总正文上限 180000 字符。超限显式返回需缩小选择的错误，不静默截断或自行丢弃阶段。
- 修复浏览器全局 execWorkspace 残留导致误执行：真实模式、当前需求、当前阶段、有效计划须同时匹配。需求切换或关闭真实模式后不能继续借用旧计划。
- 真实路径不读取 `PFC_ALLOW_STAGE_BYPASS` 绕过门禁。验证使用工厂按真实阶段规则构造前置事实；直接跳阶段的测试只能归入专用负例。

### A5 预算与验证证据

- 新补充额度归属独立 package ID 和绝对路径账本，继承旧账本摘要用于审计；旧账本只读，不清零、不冲销失败尝试。每次派发有唯一 attemptId，预留/结算幂等，未完成预留必须核验而非释放后重发。
- 新统一入口默认只规划；显式选择 offline/integration/real。默认命令不消耗真实调用，不把跳过真实项写成 PASS。
- 断言 `status` 保留 PASS/FAIL/BLOCKED，`httpStatus` / `jobState` 另存。顶层结论同时核查 exit code、断言数、errors、清理读回和源码指纹；附加字段不能改写断言结论。
- 陈旧报告显示 HISTORICAL，缺少本次证据显示 BLOCKED；分支差异只作用于精确分支断言，其他错误继续阻断。取消 runner 中自动 checkout/clean；证据写到新 runId 目录，旧报告保持原样。
- 本轮新增闸和 23 号九条基础入口是第一批修复验收；完整 44/C4 回归仍是整个 AI/工具包的退出条件。旧 49 条须逐项迁移到安全输出路径并在最终业务链路上重跑后才能声明全量通过，本次不以局部闸替代。
