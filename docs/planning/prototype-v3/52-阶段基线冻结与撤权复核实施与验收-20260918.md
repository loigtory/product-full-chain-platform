# 52-阶段基线冻结与撤权复核实施与验收-20260918

> 承接：50 号待办第 3 项「阶段基线冻结/撤权复核 UI 化」——owner 在阶段开始冻结执行基线（工作区 + 允许文件/命令 + 限额 + 有效期），阶段结束做差异复核，无违规后撤权。
> 状态：**已实施，迁移 + 服务层 + HTTP + 浏览器全链路验收通过**。本轮改动**未提交 git**，待用户确认后统一提交（与 50/51 号同批）。

## 一、背景与决策

- 51 号完成审批卡片 UI 与决策审计，但「阶段级执行授权」仍缺少显式入口：freezeForActor 已有服务实现，界面无从发起，基线冻结/复核/撤权全链未闭环。
- 52 号目标：以「阶段执行基线」为单位的**冻结 → 执行 → 差异复核 → 撤权**生命周期：
  - **冻结**：owner 在 dev 阶段指定工作区 + 允许文件（glob）+ 允许命令 + 限额 + 有效期，服务端扫描工作区生成 baselineHash 落库（stage_plans 表，008 迁移）；
  - **复核**：阶段结束扫描工作区当前状态与基线对比，输出 changes/outOfScope/violates；
  - **撤权**：仅复核无违规可撤；撤销后为终态，可重新冻结开启新周期；
  - **不可变契约**：DELETE 禁止、契约字段（workspace/control/baseline_*）冻结后不可变更（revoked→frozen 新周期除外）。

## 二、实施内容

### 2.1 数据库迁移 008：stage_plans 表 + 触发器

`server/sql/m2c/008-stage-plans.sql`：

- `stage_plans` 表：requirement_id（唯一）/ stage / state（none|frozen|revoked）/ workspace / control(jsonb) / baseline_hash / file_count / review(jsonb) / created_at / frozen_at / revoked_at / revoked_by；
- 触发器 `trg_stage_plans_immutable`（CREATE OR REPLACE，重置重迁可幂等）：
  - DELETE → `STAGE_PLANS_IMMUTABLE`；
  - 非 `revoked→frozen` 的契约字段（workspace/control/baseline_*）变更 → `STAGE_PLAN_INPUT_IMMUTABLE`；
  - `revoked→frozen` 允许（新周期，重置 review/revoked_*）；
  - revoked 后除 frozen 外状态变更 → `STAGE_PLAN_TERMINAL`。

### 2.2 迁移注册修复（本轮根因修复）

`server/src/persistence/migrations.js`：

- **根因**：`registry(target)` 中 007 分支写死 `if (target === '007')`——target=008 时 007 迁移不进 registry，`rows.length !== expected.length` → `MIGRATION_NOT_READY`（实测 count 7 vs expected 3）；
- 修复：007 分支改 `['007','008']`；assertReady 各版本分支数组（`['003'..'007']` 等）循序补 008。

### 2.3 阶段计划服务

`server/src/agent/stage-plan.js`（新增）：

- `freeze(ctx, req, stage, { workspace, control })`：owner 专属 + stage===req.stage；独立事务取 `contextHash = stageSnapshot(...).hash` 作为上下文锚点；扫描工作区（scanWorkspace：忽略 .git/node_modules、禁链接、敏感路径正则）生成 baselineHash/fileCount；
- `get`：任意成员可读（ownerOnly=false）；
- `review`：owner 专属；重新扫描对比基线 → changes/outOfScope/violates 落 review；
- `revoke`：owner 专属；violates=true 时拒绝 `STAGE_REVIEW_VIOLATIONS`；
- `fail()` 修复：原「构造错误不 throw」→ 改为 throw（否则错误被吞）。

### 2.4 路由

`server/src/routes/agent.js`（修改）：`stageReq()` 助手 + 4 个路由：

| 方法 | 路径 | owner | 说明 |
| --- | --- | --- | --- |
| GET | `/api/agent/requirements/:reqId/stage-plan?stage=dev` | 否 | 当前计划（无则 state=none） |
| POST | `/api/agent/requirements/:reqId/stage-plan/freeze` | 是 | 冻结（body: stage/workspace/control） |
| POST | `/api/agent/requirements/:reqId/stage-plan/review` | 是 | 差异复核（body: stage） |
| POST | `/api/agent/requirements/:reqId/stage-plan/revoke` | 是 | 撤权（body: stage） |

统一入口：`db.targetVersion !== '008'` → 409 `STAGE_PLAN_SCHEMA_REQUIRED`。

### 2.5 007/008 兼容放宽（51 号回归保护）

5188 整体升至 008 后，旧接口仍锁 007 会 409，本轮一并放宽为 007/008：

- `routes/agent.js`：status `capable`、tool-control GET 锁（51 号审批卡片数据源）；
- `domain/conversation-service.js`：停止/恢复的 job 取消分支（2 处）；
- `persistence/agent-jobs.js`：enqueue 锁（上轮已放宽，复核无遗漏）。

### 2.6 前端：阶段执行基线三态 UI

`output/pfc-workbench-prototype/original/workbench.js`：dev 阶段 exec-bar 占位替换为 `P.execBar(r, stage)` 钩子。

`output/pfc-workbench-prototype/original/domain-conversation.js`（C.install 注入）：

- `P.execBar(r, stage)` 三态渲染：
  - **none**：冻结表单（工作区 / 允许文件 glob / 允许命令 / 有效期 1-7 天）+「冻结执行基线」；
  - **frozen**：执行契约展示（工作区 / 基线哈希前 16 位 / 模式 / 允许文件 / 允许命令 / 有效期至）+ 复核结果区 +「差异复核」+（复核无违规才显示）「撤权」；
  - **revoked**：已撤权 +「重新冻结（新周期）」（直接调 freeze API 保留上周期契约）；
- remote actions：`stage-freeze` / `stage-review` / `stage-revoke` / `stage-refreeze`；
- render 钩子：dev 阶段 setTimeout 拉取 stage-plan 同步服务端状态（**仅状态/基线/复核变化才重渲染**，修复了无差别重渲染导致的 DOM 重建/输入丢失）；
- 服务端状态为准：本地「重新冻结」仅调 API，refetch 不覆盖 frozen/revoked 真实态。

`output/pfc-workbench-prototype/original/base.css`：追加 `.exec-fields` / `.exec-field` / `.exec-err` / `.exec-review` / `.exec-bar .row` 系列样式。
