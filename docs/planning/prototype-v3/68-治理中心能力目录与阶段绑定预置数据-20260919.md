> 状态：已完成并验收（seed 42 条 + 浏览器实测目录/绑定/热插拔交互通过）

> 前置：55 号阶段能力配置中心（stage_capabilities 配置表，worker 实际装载来源）

## 一、背景与问题

用户实测治理中心时发现：**能力目录"暂无记录（共 0 条）"、阶段绑定无数据**。原因：55 号交付的是 `stage_capabilities` 配置表（AgentRuns 面板 + worker 装载），而**治理中心的能力目录（caps）+ 阶段绑定（binding_sets/cap_bindings）是另一套"登记→复核→启用 + 阶段绑定"体系，从未 seed 预置数据**——两套体系并存，治理中心视图长期为空。

## 二、本次改动

### 1. seed 预置 `server/seed-55-governance.cjs`（新增，幂等）

以 `stage_capabilities` 表（55 号定稿 45 条）为唯一来源，同步到治理中心：

- **登记**：按 name 去重（同一能力只登记一次），type 映射 `skill→Skill / mcp→MCP / tool→终端工具`，src 映射 `local→本机已装 / github→GitHub 生态 / company→公司 ai-dev`，ver=1.0.0；
- **复核 + 启用**：逐条 `POST /api/caps/:id/review` + `PATCH /api/caps/:id/toggle`；
- **阶段绑定**：按 stage 聚合 capIds，`PUT /api/bindings` 逐阶段保存（binding_sets/cap_bindings）。
- 关键踩坑：① 登录用 `{origin, cookie}`（set-cookie 首段）非 Bearer；② **所有写操作需 `commandId`**（命令审计）；③ `GET /api/caps?limit=200` 超分页上限（400 INVALID_PAGINATION），用 `limit=100`；④ 登录会话满 4 个（SESSION_LIMIT）需重启服务清内存。

### 2. 后端 `capability-service.js`：bindingDto 补 caps 明细

`GET /api/bindings` 此前只返回 `stage/revision/capIds`（前端无法按绑定渲染名称/来源）。`bindingDto` 增加 `caps`（id/name/type/protocol/src/enabled）。

### 3. 前端 `governance-domain-view.js`：绑定视图重构

原视图把**能力目录当前页全部条目**渲染进每个阶段（每阶段 20 个标签 × 8 阶段，仅绑定项高亮，"5 项"与 20 个标签矛盾，视觉噪音大）。重构为：

- **只显示已绑定能力**（名称 + 来源徽标 + 启用状态；已绑定项为可点击 chip，点击即解除）；
- **操作列**：显示目录当前页未绑定项作为"＋添加"入口（最多 8 个，点按即绑定）；
- 说明文案注明"只显示已绑定能力；添加入口展示能力目录当前页未绑定项"。

### 4. 前端 `base.css`：chip / bind-ops 样式

`.chip / .chip-off / .chip-src / .bind-ops` 标签与操作列样式。
