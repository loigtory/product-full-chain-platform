# CAP-PFC-01 UI-R6 门禁中心与材料库设计检查点

## 1. 迭代分类与确认

- 分类：严格级系统迭代。原因是新增 PC Web 页面、HTTP 读契约、数据库聚合查询和本地体验数据。
- 已确认目标：把侧栏中的“门禁中心”和“材料库”从规划态变为可独立使用的运营页面，并可进入既有需求详情完成门禁运行、人工登记和材料影响处理。
- 已确认授权：本地源码写入、隔离 `codex_test_*` schema 测试写入、`pfc_experience` 合成体验数据重置/读写。
- 不在本次范围：新表或迁移、PFC-02/PFC-04 真实集成、外部环境、依赖安装、Git 提交/推送、部署和发布。
- 责任人沿用：代码评审=陈立；测试=陈立；安全=陈立。人员登记已完成，正式业务验收仍以各项实际结论为准。

## 2. 方案选择

采用“服务端聚合读模型 + 独立页面 + 复用详情处理能力”方案。

- 新增 `GET /api/v1/gate-center`：服务端聚合需求、当前基线和门禁运行，支持当前待办/历史记录、阶段、状态、模式和需求名称筛选。
- 新增 `GET /api/v1/material-library`：服务端聚合需求、基线、材料引用和待确认影响，支持基线状态、材料来源、材料用途、敏感级别和需求名称筛选。
- 浏览器对每个页面只发起一次列表读取，不逐行请求需求详情；进入具体处理时才读取该需求详情。
- 门禁中心“当前待办”每个需求只显示当前阶段的最新有效 GateRun；尚未运行时显式返回 `NOT_STARTED`。历史视图只显示真实 GateRun。
- 材料库每行代表一个基线；材料引用作为该行的受控元数据集合返回，不返回材料正文、凭据或真实客户数据。
- 沿用 `/requirements/:id` 详情和既有门禁/材料影响写接口，避免复制状态机和权限判断。

未选方案：前端先读取需求列表再逐条读取详情。该方案会产生 N+1 请求、错误状态分散且不利于统一筛选，因此不采用。

## 3. 契约与交互

### 3.1 门禁中心

- 路由：`/gate-center`。
- 视图：`CURRENT`（当前待办）和 `HISTORY`（历史记录）。
- 状态：`NOT_STARTED`、`IN_PROGRESS`、`PASS`、`BLOCK`、`WARN`、`UNKNOWN`。
- 模式：全部、`AUTOMATIC`、`MANUAL`；未运行项模式为空。
- 行信息：需求、需求当前阶段、目标阶段、当前状态、运行模式、有效性、责任人、时间和下一步。
- 行操作：点击需求名称进入详情；返回时恢复原中心页面与筛选状态。

### 3.2 材料库

- 路由：`/material-library`。
- 基线状态：`CURRENT`、`HISTORICAL`、`CANDIDATE`。
- 行信息：需求、版本、状态、来源、用途、敏感级别、引用数量/元数据、待确认影响和确认时间。
- 行操作：点击需求名称或“处理影响”进入详情；具体确认仍由详情中的材料影响面板完成。

### 3.3 页面设计基线

- 面向产品与交付运营人员的桌面工作台，使用紧凑表格、分段控件和可扫描的状态标签，不使用营销式大标题或装饰卡片。
- 继续使用现有中文系统字体栈、4/8px 间距、语义颜色 token、Lucide 线性图标和 4-6px 圆角。
- 主体正文保持清晰对比；颜色不是唯一状态信号；按钮具备可见焦点、禁用和加载反馈。
- 页面路由可深链，主导航显示当前位置，关键列表具备加载、空、错误和重试状态。
- UI/UX 技能包的设计查询脚本在本机安装中为失效路径占位文件，因此本次以已读取的内置可访问性、信息密度、导航、状态和动效规则为基线，不安装额外资源。

## 4. 数据设计

- 数据源：本地 PostgreSQL 生命周期表，仅使用合成数据。
- 测试 schema：每个持久化测试使用固定 `codex_test_ui_r6_*` schema，测试前重建、测试后删除。
- 体验 schema：`pfc_experience`，所有新增记录保持 `CODEx_TEST_EXPERIENCE_` 前缀。
- 工厂场景：未运行当前门禁、自动历史门禁、手工门禁、当前/历史/候选基线、有效材料引用、待确认材料影响。
- 业务有效性：候选基线必须属于同一需求且版本递增；待确认影响同时绑定当前基线和候选基线；门禁阶段与需求生命周期一致。
- 边界/负向：非法筛选值 400、无权限行不返回、历史视图不制造未运行记录、材料元数据不包含正文或凭据。
- 隔离与清理：测试 schema 在 `afterAll` 删除；体验验收产生的临时数据通过精确 schema 重置恢复到确定性种子。
- 敏感数据：只使用合成名称、ID、引用位置和时间；报告及终端不打印数据库连接串或密码。

## 6. 版本、出口与延后项

- 当前版本：UI-R6。出口条件为契约、聚合查询、页面、权限收敛和真实体验读回完成，Quick/Core/Full 均通过。
- 回滚：源码按 UI-R6 文件范围撤销；数据库无结构变更；体验数据可由 `npm run db:experience:setup -- --reset` 恢复。
- 进程：开发期间最多保留本地 API、Vite 和 PostgreSQL；浏览器与测试进程在验收后关闭。用户要求继续体验服务时，仅保留 API/Vite/PostgreSQL并报告 PID、端口和停止命令。
- 发布：本次不发布。正式验收、实名评审/测试/安全责任人、PFC-02/PFC-04、G10-G12、发布后观测仍为阻断/延后项。
