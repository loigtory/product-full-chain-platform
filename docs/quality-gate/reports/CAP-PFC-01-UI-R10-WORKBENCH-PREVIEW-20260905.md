> 结论：工程验证通过，产品负责人视觉验收不通过；原 92/100 自评撤回，不替换正式工作台，不进入发布。

## 1. 范围与证据边界

本次只新增 `/ui-preview/workbench` 独立预览页，并扩充 `packages/ui` 中的设计 token 与运营组件模板。页面通过现有同源 GET API 读取本地 PostgreSQL 数据，不提供新建、修改、推进、门禁运行或其他写入入口。正式 `/` 工作台、数据库结构、接口契约及业务数据均未变更。

测试数据策略：单元与 E2E 使用带 `CODEx_TEST_` 前缀的确定性合成响应；实际浏览器复核使用本地数据库既有数据，只读不造数，因此无 createdIds 和清理项。未输出数据库连接信息、凭据或客户数据。

## 2. 实现结果

- 统一 65px 顶栏、1280px 主容器、冷灰画布、白色内容表面和慧择青品牌焦点。
- 阅读顺序固定为业务概览、聚合筛选、搜索与视图控制、真实需求工作区、只读详情栏。
- 共享 `MetricCard`、`MetricGrid`、`WorkPanel`、`DetailSheet`，颜色、字号、间距、圆角、阴影与动效均来自 token。
- URL 保存范围、搜索、视图、排序和选中项；覆盖 hover、keyboard focus、selected、loading、empty 与 error。
- 表格与阶段视图只呈现真实返回数据，不新增虚构菜单、指标或业务状态。

## 4. 实际浏览器复核

Browser 插件在当前环境不可用。本轮最初使用本地 Edge + Playwright CLI 完成功能和布局检查，但错误地将降级证据用于视觉对标结论；产品负责人指出差距后，该结论已撤回。Playwright 仍可证明以下工程事实：

- 真实列表返回 3 条需求；指标为当前 3、阻断 1、需关注 0、覆盖阶段 2。
- 首屏、表格、阶段视图、详情栏在三档桌面宽度无横向溢出、组件重叠或文字越界。
- 搜索、筛选、视图切换、详情打开/关闭和关闭回焦可用；请求只有列表与详情 GET。
- 控制台 error=0、warning=0；React StrictMode 产生一次被取消的旧 GET，不影响结果且无旧响应覆盖。

## 5. 同尺寸差异复核与视觉结论

2026-09-05 使用 1440x900 的同一 Edge 会话重新读取参考 `/analytics` 与本地预览的浏览器计算样式。原自评没有完成这一步，且当时 `ui-ux-pro-max` 的 `scripts`、`data` 是失效路径占位文件，设计推荐库实际上未运行。

| 元素       | 参考系统                             | UI-R10                             | 判断                                     |
| ---------- | ------------------------------------ | ---------------------------------- | ---------------------------------------- |
| 全局正文   | Noto/PingFang/YaHei 优先，16/24，400 | Segoe UI Variable 优先，14/22，400 | 中文字体顺序和正文尺度错误               |
| 一级标题   | 30/36，700                           | 30/36，700                         | 主标题粗细基本正确                       |
| 指标数字   | 30/36，700                           | 30/36，700                         | 关键数字粗细基本正确                     |
| 指标标签   | 14/20，400                           | 13/20，400                         | 标签偏小，层级显得发虚                   |
| 选中筛选项 | 14/20，400，32px 高                  | 13/24，600，28px 高                | 次级操作过粗、过小、过紧                 |
| 表头       | 14/20，500，40px 高                  | 12/18，600，48px 高                | 表头字太小却太粗，留白反而过大           |
| 数据行     | 14/20，400，45px 高                  | 13/20，400，64px 高                | 信息字小、行高过松，数据密度显著低于参考 |

这组差异说明 UI-R10 只复用了颜色、卡片和大标题，没有复现参考系统的排版权重分工与高密度节奏。`92/100` 无效，当前不再给出替代性的自评分；视觉结论以产品负责人验收为 `FAIL`。

可保留的产品化差异仍包括：不复制营销 Hero、彩色入口墙和页脚；只展示现有需求、门禁、材料导航；指标由真实列表计算；详情保持只读。除此之外，字体角色、筛选控件、表头、行高、间距和品牌表达都必须重新设计和同尺寸复核。

## 6. 验收、发布与剩余风险

产品负责人已明确判定当前视觉不通过。重新设计版本通过真实浏览器同尺寸对照后，才能再次提交视觉验收，更不能提出正式工作台迁移。代码评审、测试和安全责任人现统一登记为陈立；本报告形成时未记录对应人工结论。发布环境、发布负责人、回滚、smoke、观察窗口和监控均未授权，本轮不执行发布。

剩余风险：本地数据库只有 3 条记录，极长列表、复杂阶段分布和高并发读未形成真实视觉样本；移动端不在项目范围；浏览器兼容性仅验证项目当前 Edge/Chromium 路径。

正式迁移的回滚策略是移除预览路由及新增组件引用并恢复原正式页面；本轮因未替换正式页面且未写数据库，不需要业务数据回滚。
