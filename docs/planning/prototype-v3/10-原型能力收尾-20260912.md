## 五、存储约束（既定边界）：文件本地管理，无 OSS

决策（2026-09-12 确认）：**文件不落 OSS / 对象存储，一律本地管理**。依据：内网合规（文件不出内网）、成本（无对象存储/CDN 费用）、与 Bridge 本地执行和"加载本地项目"天然一致。

**三层本地架构**
1. 执行设备本地（Bridge 设备 / 用户电脑）：工作区、项目仓库、终端产物、沙箱快照——文件归属执行端，开发作业读写本地文件与 Git，浏览器只看结果。
2. 服务端本地目录（服务器磁盘）：材料库（上传附件）、产物基线快照（baseline）、审计归档、知识库文件——统一目录规范，按需求/版本分目录，文件体原地保存。
3. 元数据库（SQLite / PG）：只存元数据——路径 · SHA-256 · 大小 · 类型 · 所属需求/版本 · 引用关系（refs）· 权限。容量条、去重、检索、审计都查库，不碰文件体。

**文件类型落位**

| 文件类型 | 存放位置 | 写入方 | 引用方式 | 容量/备份 |
|---|---|---|---|---|
| 项目/工作区 | 执行设备本地 | 开发 agent（Codex/Zed） | 路径 + Git 分支 | Git 承担版本；磁盘配额 |
| 上传材料/附件 | 服务端本地目录 | 用户上传 → 元数据入库 | 路径 + SHA-256 去重 | 配额（原型 50 MB 条即映射）；定时快照 |
| 产物基线/版本 | 服务端本地版本目录 | 确认版本时快照 | baseline 号 + 路径 | 按需归档，可设保留期 |
| 沙箱快照/回放 | 执行设备本地 | 作业执行时生成 | runId + 差异清单 | 与作业生命周期绑定 |
| 审计归档 | 服务端本地 | 动作落库 | 审计条目引用文件路径 | 只增不改 |

**影响与补充措施**
- 简化：对象存储/CDN/云上传链路移除；原型容量条 = 本地配额；上传 = 本地落盘 + 元数据入库。
- 需补充本地方案：① 目录规范与权限（谁可读哪些目录）② 文件哈希去重（同材料只存一份）③ 备份归档任务（服务端目录定时快照）④ 跨设备共享策略（Bridge 或内网共享目录，不复制文件体）。
- 代价与缓解（如实）：单点磁盘风险 → 快照备份/共享盘缓解；多人协作依赖内网共享/Bridge（部门级规模足够）；横向扩展受限 → 部门内网工具 GB~TB 级完全够。

状态：**工程实现既定边界**，后续架构与实现不再引入对象存储。
